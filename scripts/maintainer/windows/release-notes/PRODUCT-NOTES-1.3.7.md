本版相对 **1.3.6**：员工在部门群起的后台任务跑完后，结果会自动回到群里；同时修掉一批会让人「以为它在干活、其实早卡住了」的问题。

### 新增

- **部门群自动回执**：在群里派给员工的活如果跑得比较久，任务真正完成 / 失败 / 取消时，系统会以该员工名义往群里发一条结果气泡，并标注「自动回执」。同一次运行只发一条，不会刷屏——你不用再盯着屏幕猜它到底跑没跑完。

- **MCP 状态跨进程可见**：以前在平台工具或命令行里查 MCP 服务，总显示「未加载」，因为状态只存在起它的那个进程里。现在能看到别的进程落下的真实状态；本进程确实看不到时会明确写「未知」并给出原因，不再用「加载中」敷衍。

### 改进

- **会话列表更紧凑**：行高、图标、字号都下调一档，同样一屏能多看几行会话。
- **群聊读起来更顺**：打开群聊回填历史时，不会再把你刚发的消息冲掉；你往上翻旧消息时，也不会被新消息拽回底部。
- **员工回合交代更清楚**：在部门群里起了后台任务的回合，员工必须在正文里报出任务名，并说明完成后会自动回执，不再无声结束。

### 修复

- **子任务失败后整条流程卡死**：上游步骤失败 / 超时 / 取消时，下游会永久停在「等待派发」，工作流一直显示执行中，直到你手动去停。现在失败会沿依赖链一路把下游阻断，并继续排下一波。

- **会话可以被别人抢走**：用同一个会话键重建会话时，原先会强制改写归属和标题，任何登录用户都能抢走可枚举的键（比如部门群会话）并读到历史。现在非本人、非管理员一律拒绝。

- **只声明 read 的步骤跑了 58 次 bash**：步骤里显式声明的工具清单被当成「至少这些」，自动扩族成 bash / write 全家桶。现在声明即上限，不再自动放大。

- **员工配置里的 MCP 工具全被判未知**：命令行这类冷进程没有运行时缓存，`mcp__server__tool` 一律判为未知工具。现在按同一份配置里的 mcp_servers 做背书。

- **声明不支持 thinking 的模型被厂商打回 400**：这类模型被硬塞 thinking 参数，走 OpenAI 兼容代理的 Claude 等直接报 400。现在对它们一律不发 thinking 参数。

- **群里执行中重复 @ 会重复跑一轮**：一轮模型回合常远超 8 秒合并窗口，期间再 @ 会另起完整一轮，重复回复、重复计费。现在执行中的重复点名会并入当前这一轮。

- **切部门时回复打到另一个群**：切换部门后旧队列没销毁，A 部门进行中的点名把回复写进 B 的时间线。现在切部门会强制重置。
