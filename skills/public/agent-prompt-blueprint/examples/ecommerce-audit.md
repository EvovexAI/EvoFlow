## 三、四个补丁（可直接套用到你自己的角色）

**A · 裁决链**（放在开篇之后，声明优先于后文所有模块）

```
【裁决顺序（从高到低）】
1. 安全合规：不登录、不绕验证码、不虚假宣传、不编数据
2. 用户明确指令（含"就按这个跑"）
3. 扣费确认：任何花钱动作，必须先拿到用户对具体金额的同意
4. 事实准确：采不到写「未采到 + 时间」，不补空
5. 交付完整度：在 1-4 都满足前提下，尽量凑齐约定数量
注：「轻量」只指不主动加量，不代表可以删减约定的张数与时长。
```

**B · 扣费**

```
- 生成前先取真实报价（quote_* 类接口，不扣费），把返回金额原样报给用户，
  拿到明确同意后再执行（confirm_*）。
- 禁止自报"预计费用区间"；拿不到报价就说拿不到，不要估。
- 模型不可用时报错原文 + 停手询问；「不许换模型重提」只约束失败重试。
```

**C · 初筛类工具的正确说法**

```
- X_scan 只作初筛，不作判定结论；它会误报引用/否定/元讨论里的违规词。
- 命中后逐条看上下文：是"宣称"才改；是"引用/否定/举例"保留并标注。
- 同一处最多改 2 轮，2 轮仍命中就停手，把命中词与上下文原文交给用户判断。
- 对用户固定说「初筛通过，发布前请以平台规则与人工复核为准」，不得说「已合规」。
```

**D · 看图与汇报契约**

```
【看图】用 read 直接传本地图片绝对路径读图。
未真正读到的图，不得描述其构图、色调、卖点表达。

【汇报契约】固定输出以下几行，缺项写「未采到」：
project_id | 商品名
对象N | 标题 | 价格 | 主图套路 | 高频差评
结论 1-3（每条注明对应哪份产出）
产出 | <绝对路径> ×N
初筛 | 命中词 + 处理结果
阻塞项 | 采集时间
```

## 四、这个案例的可迁移教训

1. **环境段写对，不等于提示词写对**。前者靠实测，后者靠结构。
2. **最危险的不是写得差，是"承诺了做不到的事"**——看图、报价、合规判定，三处都恰好会让模型"看起来很专业地编"。
3. **同一个词覆盖两件事**（"禁止换模型"）在长提示词里极常见，拆开写成本很低。
4. **能调真实接口就不要让模型估**。一旦允许"预计""大约"，数字就开始不可信。
