# RTCO 五段装配法

所有 system_prompt 按五段写。**段与段的职责不能重叠**——同一句话在两段里各说一遍且说法不同，是长提示词自我打架的头号原因。

## 五段职责

| 段 | 回答的问题 | 写什么 | 不写什么 |
|---|---|---|---|
| **R · Role** | 你是谁、边界在哪 | 一个窄岗位 + 一句价值定位 | 流程、格式、禁令 |
| **T · Task** | 让你干哪几件事 | 强动词（采集/生成/判定/改写/验收）+ 模块编号 | "帮我看看""尽量处理" |
| **C · Context** | 在什么条件下干 | 服务对象、输入假设、工具与真实参数、成本口径、时间口径 | 交付格式 |
| **O · Output contract** | 交出来的东西长什么样 | 固定字段/表格列/小标题、缺项取值、样例 | 说教式的"请认真写" |
| **+ · Guardrails** | 什么绝对不做 | 负向禁令、合规红线、不确定性标注方式、**裁决顺序** | 正向任务描述 |

## 强弱写法对照

| 段 | ❌ 弱写法 | ✅ 强写法 | 差别 |
|---|---|---|---|
| R | 你是专业的电商助手 | 你是竞品信息采集岗，只出事实表与对比，不写营销结论 | 加了「不做什么」 |
| T | 帮我分析一下竞品 | 按固定字段采集 3 个竞品，输出对比表 + 一句结论 | 强动词 + 数量 |
| C | 用工具去查 | 用 `fetch_url` 取正文，页码与采集时间逐条记录 | 指定工具与字段 |
| O | 输出一份报告 | 表格固定列：对象\|价格\|卖点\|来源URL\|采集时间；缺项写「未采到」 | 可解析 |
| + | 注意不要出错 | 不编造数值；采不到写「未采到 + 原因」；同一失败不重试超过 2 次 | 可判定 |

## 可判定性改写规则

一条规则能被第三方判真假，才算合格。三种改法：

1. **换成可数**：「竞品多找几个」→「默认 3 个，采不到不凑数」
2. **换成可查**：「文案要合规」→「出稿后调 compliance_scan，命中项逐条看上下文」
3. **换成可引**：「引用要准确」→「每条结论后附来源文件名 + 章节号」

反例检查法：把规则交给一个不了解业务的人，问他"你能否判断这条做到了没有"。答不出，就是不可判定。

## 篇幅档（借用画幅比的直觉）

| 档 | 段数 | 字数 | 适合 | 不适合 |
|---|---|---|---|---|
| 窄（≈9:16） | 3 段，护栏≤4 条 | <400 | 单一功能岗、分类器、客服应答 | 多工具协作 |
| 均衡（≈1:1） | 5 段齐全 | 600–1000 | 通用业务岗（多数情况选这个） | 需要长链路排期 |
| 宽（≈16:9） | 5 段 + 模块章节 + 样例 | 1500+ | 生产流水线、多工具编排 | 简单问答（会稀释重点） |

**判断方法**：模块数 × 每模块的输出契约行数 ≈ 需要的段数。超过 4 个模块就该考虑拆 Agent，而不是继续加长。

## 三段最容易写错的地方

**C 段写成说明书**。塞进大量环境细节，模型抓不住重点。环境信息只保留"会变、会失败、必须读"的部分，其余放技能或知识库。

**O 段写成愿望**。"报告要专业、结构清晰"——这不是契约。契约必须有字段名，最好有一个 one-shot 样例，字段名固定不变。

**+ 段没有裁决顺序**。多条规则并列时，冲突无解。必须有显式优先级，例如：

```
【裁决顺序（从高到低）】
1. 安全合规  2. 用户明确指令  3. 扣费确认  4. 事实准确  5. 交付完整度
说明：本条优先于后文任何模块；「轻量」只指不主动加量，不代表可删减约定张数。
```
