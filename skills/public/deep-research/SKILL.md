# 联网研究与洞察页生成（先定界、再执行）

## 技能目标

在写总结、做页面、做方案前，先完成「够用且可追溯」的联网研究，保证输出有事实、有数据、有来源、有结构。  
**研究什么角度、多深、边界在哪**，必须在开工前与用户对齐（除非用户已在首轮一次性说清）。**最终交付默认 HTML 洞察展示页**（含图表与来源区），不向用户单独问「产出形态」；模板 T01–T05 由模型按界定书自动选用。对齐后形成简短的 **《研究界定书》**，再进入检索与成稿。

## 何时必须启用

- 用户要求「解释 / 调研 / 对比 / 分析」某主题
- 需要报告、方案、演示稿、网页展示
- 需要最新信息或权威来源
- 单次搜索不足以支撑结论
- **监工执行顺序**：一旦判定走本技能，须先 `read_file` 本目录 `SKILL.md`（界定选项可再读 `research-scoping-options.md`），再 `scenario`/大规模检索；勿跳过本技能直接泛搜。终稿 HTML 落盘后，**主会话须在回复中用 `@@outputs/…@@` 交付**。

## 研究类型与维度（可组合，勿写死为「市场+技术」）

按主题灵活选择 **1～N 个研究维度**（不必每次全套），示例：

| 类型 | 典型关注点 | 常见信息源倾向 |
|------|------------|----------------|
| **技术** | 架构、标准、实现路径、成熟度、生态 | 文档、论文、技术博客、Release、RFC |
| **学术** | 理论框架、实验结论、争议点、综述 | 期刊、预印本、学者综述、机构报告 |
| **公司与商业** | 商业模式、财报要点、组织、战略 | 年报、投资者材料、新闻、工商 |
| **市场与行业** | 规模、增速、细分、玩家、趋势 | 行业报告、统计机构、头部媒体 |
| **政策与监管** | 法规、合规、区域差异 | 政府站点、监管机构、官媒政策解读 |
| **产品与用户体验** | 功能对比、口碑、场景、定价 | 评测、应用商店、社区、问卷类报告 |
| **投资与资本** | 融资、估值逻辑、赛道资金动向 | 财经媒体、招股书、数据库摘要 |
| **竞争情报** | 对标、差异化、护城河 | 多公司交叉检索、第三方分析 |

**原则**：维度由 **《研究界定书》** 与用户选择决定，不要默认锁死为「市场 + 技术」；若用户只关心其中一类，就只开该类子任务或检索角度。

## 阶段 0：研究界定与方向确认（默认第一步）

在用户只说「帮我深入调研一下 XXX」或主题较泛时，**必须先做界定再大规模检索**。优先使用 **`ask_clarification`**，在问题里给出 **可直接点选的选项**（或 A/B/C…），减少用户打字负担。

**固定选项全文（复制即用）**：与本文件同目录的 **`research-scoping-options.md`**。  
其中包含：**合并一轮**、**拆两轮**、**仅补边界** 等结构参考；调用 `ask_clarification` 时用 `read_file` 读取后，将 `【在此填写主题】` 换成用户主题，并**必须按用户问题重写各题的 `options` 文案**（日报、单公司、技术选型等场景的切片完全不同）。**`options` 字符串内不要写序号或 A/B**（由客户端统一展示编号）。

### 选项必须与用户问题同类（强制执行）

1. 先从用户原话提取：**主题实体、时间粒度（今日 / 本周 / 不限）、任务形态（快讯梳理 / 深度研判 / 选型对比 / 单主体拆解）**。  
2. **多选维度题的每一条 option**：应是该主题下合理的研究切片，并尽量复用用户用过的名词（例如「今日 AI 要闻」「×× 产品线」「中国大陆监管口径」）。  
3. **禁止**：用户在谈「日报 / 简报 / 舆情」时，却把「学术综述」「投资估值模型」等作为主选项堆砌；**宁少勿偏**，可只给 4～5 个高相关项 +「其他（请补充说明）」。

### 建议一次问清的维度（与选项文件对应）

1. **研究角度 / 切片**（可多选）：**与用户问题强相关**，忌套用与用户无关的通用九宫格（例如用户要「今日 AI 要闻」却给「学术综述 / 投资资本」作主选项）。  
2. **深度档位**（单选：快速 / 标准 / 深入）  
3. **核心问题一句话**（可合并进题干或第二轮）  
4. **边界**（地域、时间、语言、排除来源等；可用补充说明收集）  

**不问**：产出形态（固定默认 HTML）；HTML 模板编号（由模型在界定书中选定 T01–T05 并写明理由）。

### 可跳过阶段 0 的情况

若用户首轮已明确给出：**主题 + 研究角度 + 深度 + 必要边界**（以及一句话核心问题），则视为界定已完成，直接整理为《研究界定书》（写明默认 HTML 产出与模板倾向），**无需再问**。

### 《研究界定书》（内部锚点，可写入 Plan/子任务描述）

用 5～10 行 bullet 固化阶段 0 的结论，供后续子任务与汇总引用，避免跑偏。至少包含：研究角度、核心问题、深度、边界、**默认产出 HTML**、**模板选型（T01–T05）及理由**、**建议交付文件名**、**终稿交付：主会话回复 `@@outputs/…@@`**。

## 核心原则

- 不要只靠常识直接下结论  
- **先界定、后放量检索**：未对齐前不要默认开满并行子任务  
- 默认在界定书范围内做「够用优先」；**深度档位由用户选**  
- 全文阅读按需：摘要不足再抓全文  
- 输出须含来源与可核验事实  

## 研究流程（与深度档位挂钩）

### 快速

1. 1～2 轮查询形成最小证据集  
2. 覆盖界定书中的 **1～3 个关键维度**（不必凑满）  
3. 保留最重要 3～5 条事实/数据 + 来源  

### 标准（默认）

- 在界定维度上各有关键来源  
- 适度补充风险、限制或反方观点  
- 子任务与检索轮次按界定书伸缩（见下节）  

### 深入（仅当用户选择或界定书要求）

- 增加查询轮次与同义改写  
- 对 1～2 个权威来源做全文阅读  
- 可 **增加并行研究子任务**（每维度或每大块问题一个），仍应用 `depends_on` 汇总到成稿子任务  

## 任务委派模式（弹性拓扑：先对齐界定书，再定子任务数）

当任务包含「联网研究 +（可选）输出网页」时，**子任务数量与分工由《研究界定书》决定**，以下为 **推荐默认**，非硬性上限。

### 推荐默认（用户未指定复杂维度时）

- **2 个并行研究子任务 + 1 个汇总成稿子任务**（共 3 个）  
  - 研究子任务按界定书拆分维度（例如「市场 / 技术」「公司 / 政策」），**不要机械固定为「市场+技术」**  
  - 汇总子任务：去重、对齐核心问题；**对外默认可演示交付为 HTML**（中间 Markdown 小结可保留）  

### 扩展（界定书维度多或「深入」档）

- 可改为 **3～4 个并行研究 + 1 汇总**，或 **2 轮研究串行 + 汇总**  
- 每子任务仍建议优先 `general-purpose`；仅当用户明确要求再用 `claude-code` / ACP 等  

### 智能体与速度（原则）

- 子任务 **优先** `assigned_to: "general-purpose"`  
- 默认每个研究子任务 **少量检索轮次与结果数**；**不足再迭代**，避免一次性堆复杂参数导致失败  
- **禁止**为追速度而省略阶段 0（除非用户已给全界定信息）  
- 联网检索参数：优先 `web_search`，必填 `query`，可选 `max_results`（建议 3～7，随深度档略调）；**勿传未确认可用的扩展参数**（如未文档化的 `fetch_pages` 等）  
- 读技能/模板：优先仓库内稳定路径（如 `skills/public/deep-research/...`），子任务隔离工作区中避免裸相对路径失效  

### 子任务输出契约（研究子任务）

各研究子任务返回：

1. 本子任务覆盖维度的小结（2～4 句）  
2. 关键信息点（带来源）  
3. 来源链接列表  

汇总子任务返回：

1. 合并去重后、**直接回答界定书核心问题** 的结论  
2. 可追溯来源列表  
3. 终稿 HTML：选模板、替换占位符与图表数据（默认可 T01，强展示 T05，见下）；文件写入 **`outputs/`** 后，**主监工须在回复中用 `@@outputs/<文件名>.html@@` 交付**（见下文 **向用户展示产物**）。  

### 子任务创建提示（`supervisor(create_task_with_subtasks)`）

- 各研究子任务写明对应界定维度；`assigned_to: "general-purpose"`  
- 汇总子任务 `depends_on` 指向全部研究子任务；在汇总子任务 `instruction` 中明确写出：**终稿保存路径（`outputs/…html`）**，并写明 **完成后由主会话在回复中用 `@@outputs/…@@` 交付**。  

## 模板选取与网页生成

模板目录：`skills/public/deep-research/templates`

| 模板 | 适用场景（与界定类型对应，可override） |
|------|----------------------------------------|
| `T01-general-summary.html` | 泛主题、多源综合、未定专属形态 |
| `T02-company-overview.html` | 单公司主体、商业与组织信息 |
| `T03-competitor-compare.html` | 多方案/多产品对比与选型 |
| `T04-event-timeline.html` | 事件演进、阶段、影响 |
| `T05-strategy-insight.html` | 强演示、变化信号、风险热度、咨询风展示 |

**选型**：在《研究界定书》中写明选型理由；若用户要「震撼演示」倾向 T05。  

### T05 使用时的数据诚实约束

- 图表数据必须来自真实检索，禁保留模板示例数  
- 填写 `CHANGE_*_DELTA`、`RISK_*_LEVEL` 等字段时须与证据一致  

### 生成 HTML 步骤（标准）

1. 选最匹配模板（以界定书为准）  
2. 复制模板并重命名（见下节 **文件命名**，不得保留 `T01-…` 等模板原名）  
3. 映射 `{{...}}` 占位符  
4. 关键数字写入图表 `labels/data`  
5. 保留来源字段可追溯  
6. 浏览器检查排版与结论一致性  

### 交付 HTML 文件命名（必须）

- **优先中文**：从用户原话与《研究界定书》抽取**主题 / 对象 / 时间窗口**等组成短文件名，使用户从文件名即可看出「这份分析是关于什么的」。  
  - 示例：`2026年5月6日-AI行业要闻-洞察页.html`、`某某公司-竞争态势-洞察页.html`、`端侧大模型选型-对比结论.html`  
- **禁止**直接沿用模板库内文件名（如 `T01-general-summary.html`）。  
- **禁止**在文件名中使用 `\\ / : * ? " < > |` 等路径非法字符；过长时保留主题关键词 + 日期即可。  
- 界定书中可增一行 **「建议交付文件名：…」**，供子任务写入路径与后续展示一致引用。  

### 向用户展示产物：用 `@@outputs/…@@`

- EvoFlow 中 **向聊天界面挂载可点击、可预览的交付文件** 的方式是在主会话回复里写 **`@@outputs/<文件名>.html@@`**（不是裸路径、Windows 绝对路径或 http 外链）。  
- **子智能体** 可将终稿 HTML 写到 **`outputs/`**（如 `outputs/2026年5月-AI日报-洞察页.html`）；**收尾由主监工在回复中用 `@@outputs/…@@` 交付**，路径与界定书/Plan 中「建议交付文件名」一致。  
- **流程要求**：HTML 落盘且自检通过后 → **同一轮或紧随其后的主会话轮** 在回复中写出 `@@outputs/<文件名>.html@@`；**禁止**「文件已写好」却不在回复中交付就结束协作。  

## 搜索策略要求

### 时间感知（必须）

先读取当前日期再构造查询。用户说「今天 / 本周」须用「月+日+年」级时间词。

### 查询优化

- 主题 + **界定维度词** + 时间/地域  
- 多语言、同义词轮替  
- 需要权威材料时加：`report` `whitepaper` `official` `annual report` 等  

## 输出结构（研究结论，可按界定书删减）

1. 执行摘要（对齐核心问题）  
2. 关键数据  
3. 关键发现  
4. 案例/证据  
5. 风险与限制  
6. 结论与建议  
7. 来源列表  

## 常见错误

- **跳过阶段 0**，默认按固定「市场+技术」开干  
- 子任务数与维度与用户真实需求不匹配  
- 检索过少或过散、缺少来源  
- 只写正面不写风险与限制  
- 模板与界定类型不符  
- **未在回复中写 `@@outputs/…@@`**，用户侧看不到已生成的 HTML  

## 最终产出要求

- **界定清晰**：与用户确认的角度、深度、边界一致  
- 有研究深度：证据匹配界定书；**默认交付 HTML 洞察页**，结构清晰、可演示  
- **用户可点开**：终稿路径已在主会话回复中以 **`@@outputs/…@@`** 交付，非仅磁盘存在  
- 有业务价值：结论可执行、可追溯
