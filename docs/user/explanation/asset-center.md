# 资产中心

> **资产中心统一管理记忆、画像、思考、反思与经验。**
>
> 你平时只要在对话里说：
> - **「记住……」** → 记成一条事实  
> - **「把这套做法沉淀成经验」** → 写成可复用的本事  
> - **「记一下今天的反思」** → 写进当日反思  
>
> AI 会直接写进本地文件。你打开 **侧栏 → 资产中心**（`#/assets`），主要是**看看写了啥、改个错字**，不是天天填表。

**对齐结论（画功能全景图时以此为准）：**

- 一个用户拥有自己的**记忆**与**画像**；  
- 多个 AI 员工各自拥有**独立的记忆与经验**；  
- **用户画像**可在授权范围内给这些 AI 员工复用；  
- AI 员工的**独立记忆互不共享**。

用户记忆与 AI 员工记忆是**平行、独立**的关系，不是上下级，也不是记忆传递关系。

操作见 [资产中心使用指南](../guides/configuration/asset-center.md)。

---

## 1. 正确架构（左右平行）

```text
                    EvoFlow 资产中心
         统一管理：记忆 · 画像 · 思考 · 反思 · 经验
                              │
          ┌───────────────────┴───────────────────┐
          │                                       │
   【用户资产】                              【AI 员工资产】
   · 用户记忆（操作、交互、偏好、经验）      · 员工 A · 独立记忆
   · 用户画像（可授权共享给 AI 员工）        · 员工 B · 独立记忆
                                            · 员工 C · 独立记忆
          │                                       │
          └─────────── 共享规则 ──────────────────┘
     AI 员工可使用当前用户的画像（授权范围内）；
     彼此不共享各自的独立记忆。
```

左右两侧是**平行关系**。共享的是「对用户的认识」（画像），不是员工之间的工作经验。

---

## 2. 四条规则

| # | 规则 | 说明 |
|---|------|------|
| 1 | **主 Agent = 用户交互入口** | 主 Agent 对话与操作形成的长期记忆，**归属于用户**；不必再单独建一套「主 Agent 记忆」 |
| 2 | **用户记忆独立存在** | 保存用户的操作习惯、交互偏好及相关记忆信息 |
| 3 | **AI 员工各有独立记忆** | 员工 A / B / C 各自拥有工作记忆、反思与经验，**彼此不共享** |
| 4 | **用户画像可以共享** | 不同 AI 员工可读取**获得授权**的用户画像，了解偏好与工作要求 |

---

## 3. 例子：两个员工，共享的是画像不是经验

| 角色 | 独立积累的内容 | 能否被另一员工直接读到 |
|------|----------------|------------------------|
| **AI 员工 A · 电商运营** | 商品分析、选品判断、运营复盘等经验 | 否 |
| **AI 员工 B · 自媒体运营** | 内容策划、标题优化、平台发布等经验 | 否 |

假设用户画像中有一条：

> 用户偏好：所有运营分析报告先给出结论，再说明原因，最后提供执行建议。

则 A 与 B **都可以**在授权范围内使用这条画像，按相同偏好服务用户。  
**共享的是对用户的认识，而不是 AI 员工之间的工作经验。**

## 4. 资产中心功能全景图应怎么画

建议分成五部分（不要画成「用户记忆向下分发给员工」）：

| 部分 | 内容 |
|------|------|
| **一、用户资产** | 用户记忆、用户画像，以及用户侧长期交互与经验沉淀 |
| **二、AI 员工资产** | 每个员工独立的记忆、思考记录、反思与经验 |
| **三、资产管理机制** | 记忆提取、沉淀、检索、更新、查看、管理等 |
| **四、画像共享机制** | 各 AI 员工在授权范围内使用用户画像；**不**直接共享彼此记忆 |
| **五、记忆与经验再利用** | 用户后续交互调用自己的记忆；员工执行任务时调用**自己的**记忆与经验，并可参考用户画像 |

## 5. 和「知识库」有什么不同

| | 资产中心 | 知识库 |
|--|----------|--------|
| **存什么** | 画像、偏好事实、过程记录、反思、专长经验 | 你整理的文档 / Vault 笔记 |
| **谁写入** | 多半是对话里 AI 自动写；你也可侧栏快捷沉淀 | 你导入或编辑文档 |
| **入口** | 侧栏「资产中心」 | 侧栏「知识库」 |

记忆 / 经验存的是「你是谁、你喜欢什么、做过什么 / 怎么做」；知识库存的是「某份材料正文」。两者 AI 都可能参考，但**不是同一套东西**。

旧侧栏「记忆」入口会转到资产中心「记忆」Tab，不是两个功能。

## 6. 你平时怎么用（推荐）

1. **对话里说一句**（主路径）  
   - 记录：`记住我默认用 Python`  
   - 沉淀经验：`把刚才这套排查沉淀成经验`  
   - 反思：`记一下今天的 wrap-up`  
2. **需要时打开资产中心**  
   - 看**用户侧**：记忆、画像  
   - 看**某个员工**：该员工独立的记忆、经验、反思  
3. **发现记错了**  
   点开文件改两行 → 保存。下一轮就会按新内容来。

聊天侧栏「信息」里也有 **记录 / 沉淀经验 / 反思** 快捷按钮，等价于立刻落盘。主 Agent 对话沉淀进**用户资产**；与某个 AI 员工对话 / 值班产生的沉淀进**该员工资产**。

## 7. 页面里有什么

| Tab | 你能看到什么 |
|-----|----------------|
| **画像** | 用户画像、身份边界等（可授权给 AI 员工参考） |
| **记忆** | 站立摘要、事实、过程记录（随当前查看的实体：用户或某个员工） |
| **经验 / 专长** | 沉淀下来的本事（`craft`）；可晋升为自定义技能 |
| **反思** | 按日的反思日志 |
| **统计** | 引用次数、冷资产、待整合草稿；可「整合 inbox」或「全库扫描」 |
| **导出** | 打包备份；「应用到…」是**显式拷贝**，不是员工间默认共享记忆 |

> 「导出 Pack」是实体资产备份。整套「员工 + 工作流 + Agent应用」分发见 [资源包与资源市场](../guides/configuration/resource-packs.md)。

回复气泡下若出现**引用标签**，点一下可跳到对应资产文件。

## 8. 系统还会自动做什么

- 对话告一段落后，会把偏好与可复用经验整理进**对应实体**的资产（用户或当前员工）  
- 软件启动时，也会扫一遍未整理的草稿并尝试合并  
- 长对话被压缩后，助手更倾向用资产检索补细节，而不是只靠摘要猜

可用环境变量关闭（一般保持默认），见仓库根目录 `.env.example` 中的 `EVOFLOW_ASSET_*`。

## 9. 常见问题

**Q：我必须每天来资产中心维护吗？**  
不必。日常靠对话里说「记住 / 沉淀 / 反思」；资产中心是翻看与校对。

**Q：记错了怎么办？**  
打开对应文件改掉并保存；或删掉明显过时的文件。统计页里的「冷资产」可帮你找久未使用的条目。

**Q：和知识库该放哪边？**  
偏好、习惯、个人/岗位经验 → 资产中心；制度、手册、长文档 → 知识库。

**Q：员工和用户的记忆是分开的吗？会互相看见吗？**  
分开，且**平行独立**。员工之间不共享工作记忆；可共享的是授权范围内的**用户画像**。需要把某份文件拷给另一实体时，用「导出 → 应用到…」（显式拷贝，不是默认共享）。

**Q：主 Agent 有没有单独一套记忆？**  
没有。主 Agent 是用户交互入口，长期记忆归**用户资产**。
