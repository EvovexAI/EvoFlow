# 任务中心：用户待办 · 小V 协调 · AI 员工协作

> **一句话**：EvoFlow 任务中心 = **用户待办管理** + **AI 员工任务协作** + **任务执行追踪** + **结果交付**。  
> 它不只是任务列表，而是连接用户、**小V（全局 AI 小秘书）**、AI 员工组织与业务执行流程的**协同中心**。

侧栏入口：**任务中心**（`#/tasks`）。面板操作见 [任务中心使用指南](../guides/tasks/task-center.md)。

正式功能全景图建议命名：**EvoFlow 任务中心功能全景图**。

---

## 1. 重新定义

任务中心同时管两类「事」，可关联、**不是同一概念**：

| 概念 | 是什么 | 典型去向 |
|------|--------|----------|
| **用户待办事项** | 用户需要完成或关注的事情 | 自己处理，或经小V / 用户转为 AI 执行任务 |
| **执行任务（协作任务）** | 具体交给 AI 员工（或流程）处理的工作 | 状态追踪、汇报、确认与交付 |

原先对齐的任务管理、执行追踪、工作流协同、结果交付仍然保留；并明确两个核心能力：

1. **AI 员工之间的任务派发与协作**（尤其上下级分配）  
2. **用户待办事项管理**（对话 / 小V / 任务中心添加；小V 可派给合适员工）

---

## 2. 小V = 全局 AI 小秘书

**小V** 是 EvoFlow 的全局智能秘书，**不是**某个 AI 员工，也不是局部聊天助手。

| 职责 | 说明 |
|------|------|
| 全局对话入口 | 用户随时与小V沟通 |
| 待办事项管理 | 通过对话添加、查看、管理用户待办 |
| 任务派发 | 将待办或工作要求分配给合适的 AI 员工 |
| 进度查询 | 帮助了解任务执行情况 |
| 结果反馈 | 将员工完成的工作反馈给用户 |
| 跨员工协调 | 协助用户与不同 AI 员工协作 |

**小V**面向用户做待办与协调；**AI 员工**是具体工作执行者。两者职责不同。

---

## 3. 六大功能模块

| 模块 | 功能说明 |
|------|----------|
| **01 用户待办事项** | 添加待办、对话创建、待办管理、完成状态、待办转任务 |
| **02 任务创建与派发** | 用户派发、小V 分配、AI 员工之间派发、上下级任务分配 |
| **03 AI 员工协作** | 上级分配下级、员工间协作、子任务拆分、进度汇总 |
| **04 任务执行与追踪** | 任务状态、执行进度、负责人、执行记录、异常处理 |
| **05 工作流与自动化联动** | 启动预设工作流、查看执行状态 / 进度 / 结果、查询执行记录 |
| **06 任务交付与反馈** | 执行结果、员工汇报、任务确认、历史记录、结果反馈 |

说明：

- 子任务拆分、异常处理、自动分配规则等机制，以产品实际实现为准，概念上保留能力位。  
- **工作流联动不含「业务参数传递」**——当前产品未将该能力作为任务中心 / 工作流联动能力对外承诺；出图时不要画这一项。

## 4. 重点：用户待办事项

示例：用户对小V说「明天帮我检查店铺最近销售数据，看看有没有异常。」  
小V 可先记为**用户待办**，再按内容、时间与合适员工，转换为或派发为**执行任务**。

```text
用户 ──对话 / 小V / 任务中心──► 我的待办事项（记录、要求、时间、状态）
                                      │
                    ┌─────────────────┴─────────────────┐
                    ▼                                   ▼
             人工待办（用户自己处理）              AI 执行任务（派给对应员工）
                    │                                   │
                    └──────── 统一查看进度 / 反馈 / 完成状态 ────────┘
```

| 路径 | 谁创建 | 谁跟进 |
|------|--------|--------|
| 任务中心「我的事项」 | 用户 | 用户自办，或点派发 → 协作任务 |
| 对小V / 主 Agent 说话 | 小V 或对话落库 | 小V 可选员工派发 |

面板里「我的事项」对应本概念中的**用户待办**；「协作任务」对应**执行任务**。

---

## 5. 重点：AI 员工之间的任务派发

与 AI 员工组织架构直接关联。示例：

```text
电商运营主管 AI 员工
  ├─ 接收任务 · 分配工作 · 汇总结果
  ├─ 选品员工（商品筛选与分析）
  ├─ 文案员工（标题与卖点）
  └─ 数据员工（销售数据分析）
        │
        ▼ 下级汇报执行结果
  主管汇总 → 向用户反馈进度与成果
```

任务中心不仅记「用户 → 员工」，还应能呈现：

- AI 员工 A 派发给 AI 员工 B  
- 上级派发给下级  
- 原始任务与拆分子任务的关联  
- 下级向上级的进度与结果反馈  
- 上级汇总后向用户的最终交付  

目标是**可展示完整派发关系**，而不只是一张平面任务列表。  
岗位交工 / 同意派发 / 跨岗叫醒等细则见 [智能体员工概念](smart-employees.md)。

### 派发完成后向谁交付（产品约定）

当员工 A 把任务派给员工 B 时：

| 策略 | 说明 |
|------|------|
| **默认** | B 完成后**先向派发者 A 汇报**；由 A 汇总或确认后再向用户交付 |
| **可配置** | 按任务要求允许 B **直接向用户交付** |

这样既符合上下级组织关系，也兼容普通员工之间的协作。

## 6. 三个主要视角（同一套数据，展示重点不同）

| 视角 | 面板对应（现名） | 展示重点 |
|------|------------------|----------|
| **我的待办** | 我的事项 | 用户自己要处理、小V 记下的、或已委派给员工的待办 |
| **任务管理** | 协作任务 | 来源、负责人、状态、优先级、过程、交付结果 |
| **员工协作任务** | 协作任务中的树 / 派发与汇报关系 | 上下级派发、拆分、执行进度、汇报链 |

出图时可按三视角分区，底层仍是同一套任务数据。

## 7. 核心关系（出图用）

```text
用户
  直接操作 / 对话 / 添加待办
        │
        ▼
小V · 全局 AI 小秘书
  待办管理 · 任务派发 · 进度查询 · 结果反馈
        │
        ▼
EvoFlow 任务中心
  用户待办事项 · 任务创建与派发 · AI 员工协作 · 进度与结果追踪
        │                    │
        ▼                    ▼
 AI 员工体系              工作流 / 自动化
 上下级派发、协作、汇报    预设流程执行、进度与结果查询
 （无业务参数传递能力位）
```

## 8. 关键原则

1. 用户可直接创建待办，也可通过**小V**和对话创建待办。  
2. 小V 可以把用户待办派发给合适的 AI 员工。  
3. AI 员工之间可以相互派发，尤其支持上下级分配。  
4. 任务中心统一追踪状态、过程与结果交付。  
5. 与工作流、[自动化中心](automation-center.md)、Agent 应用保持联动，**不混淆各模块职责**；工作流侧不宣称「业务参数传递」。自动化到点触发 ≠ 员工主动值班。  
6. 与[资产中心](asset-center.md)一致：员工间可派发任务、协作并传递**必要的任务信息**，**不等于**共享彼此长期记忆；员工独立记忆仍隔离，可共享用户画像。

---

## 9. 后续出图统一遵守

- 全局小秘书统一称 **「小V」**（勿写「小助手」）。  
- 小V 负责面向用户的待办、派发与协调。  
- AI 员工之间允许派发，尤其上下级。  
- 任务中心同时管理用户待办与 AI 执行任务。  
- 工作流**不**展示尚未支持的业务参数传递。  
- AI 员工可协作，独立记忆仍不共享。
