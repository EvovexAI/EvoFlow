# Agent 应用中心：业务应用接入与 AI 能力集成

> **一句话**：Agent 应用 = **业务应用承载中心** + **AI 底座能力连接中心**。  
> 它本身不一定是 AI Agent，也不一定要由 AI 生成；普通业务系统接入后，可以继续用工作流、AI 员工、知识库做智能化。

侧栏入口：**Agent应用**（`#/extensions`）。  
操作装法见 [模型、联网搜索、插件与 Agent 应用](../guides/configuration/settings-capabilities.md)；自研项目清单见 [将自己的项目安装为 Agent 应用](../guides/configuration/install-own-project-as-extension.md)。

正式功能架构图命名建议：**F4 · EvoFlow Agent 应用中心——业务应用接入与 AI 能力集成**。

---

## 1. 真正定位

Agent 应用中心统一做两件事：

1. **承载**：把各类业务应用放进 EvoFlow，让用户从一个入口访问与操作。  
2. **连接**：让这些业务应用能调用 EvoFlow 的 AI 底座（工作流、AI 员工、知识库），并拿回进度与结果。

它可以是：

| 形态 | 说明 |
|------|------|
| 独立静态网页 | HTML / 纯前端站点 |
| 服务器 Web 业务系统 | 已部署的业务后台、运营系统等 |
| 本地服务或应用 | 本机进程 + 可访问的网页入口 |
| 第三方网页嵌入 | Iframe / 远程 URL（取决于目标站是否允许被嵌入） |
| 为 EvoFlow 开发的 AI 原生业务应用 | 自带 Bridge / SDK，深度调用平台能力 |

最重要的一点：**普通业务系统接入后，就可以进一步使用 AI 员工、工作流、知识库等平台能力，实现业务智能化。**

---

## 2. 关键设计：统一应用列表，平台内打开

**要支持。** Agent 应用中心把多个不同来源的业务应用登记到**同一份应用列表**里（可分类、可搜索、可启停）。

用户路径：

1. 打开侧栏 **Agent应用**  
2. 在列表中看到所有已接入应用（远程、本地清单、zip、资源包装入的均可）  
3. **点击某个应用** → 在 EvoFlow 面板内直接打开并操作（通常为内嵌网页视图）  
4. 不必另开浏览器标签，也不必记住各系统各自的入口地址

因此「应用列表 + 平台内打开」是应用接入与管理的默认体验，不是可选旁路。

## 3. 六大功能模块

| 模块 | 具体能力 | 备注 |
|------|----------|------|
| **01 应用接入与管理** | 创建应用、应用列表、应用分类、应用配置、应用入口管理 | 含上文「统一列表」 |
| **02 多类型应用承载** | 静态网页、服务器 Web 服务、本地服务、第三方网页嵌入 | 承载层 |
| **03 工作流集成** | 触发指定工作流、查看执行进度 / 结果、追踪执行记录（**不含**业务参数传递） | 差异化 |
| **04 AI 员工集成** | 实时对话、任务派发、员工选择、任务进度、结果反馈 | 差异化 |
| **05 知识库集成** | 关联知识库、检索、知识问答、为业务提供知识支持 | 差异化 |
| **06 应用运行与管理** | 应用访问、身份认证、权限管理、运行状态、集成配置 | 运行治理 |

其中 **03 / 04 / 05** 体现 EvoFlow 相对「只嵌网页」产品的差异化：业务界面里真正连上 AI 执行与企业知识。

## 4. 与 AI 底座的关系（两层概念，勿混淆）

业务应用与 AI 底座相互独立，通过接口协作，而不是把所有 Agent 能力塞进每个应用内部。

```text
左侧：多类型应用接入          中间：Agent 应用中心           右侧：EvoFlow AI 底座
静态网页 / 服务器应用    →   应用管理 · 应用访问      →   工作流（触发 · 进度 · 结果）
本地服务 / 第三方系统    →   网页承载 · 集成配置      →   AI 员工（对话 · 派发 · 反馈）
                         →   运行管理 · 身份权限      →   知识库（检索 · 问答 · 增强）
                                      │
                                      ▼
                         业务智能化：业务系统 + AI 执行 + 企业知识
```

### 第一层：应用承载

把现有业务系统的界面接入 EvoFlow，统一访问与使用。方式包括静态页托管、Web 服务地址、Iframe 嵌入等。  
注意：目标系统是否允许被 Iframe 加载、本地服务是否具备可访问网络通道，都会影响能否嵌入。

### 第二层：AI 能力集成

让业务应用真正调用 EvoFlow：通过 API、SDK 或集成接口触发工作流、对话 / 派发 AI 员工、检索知识库，并接收执行状态与结果。

**嵌入一个网页 ≠ 已接入 AI。**  
只有建立业务数据与 EvoFlow AI 底座之间的交互，才算完成智能化升级。

## 5. 场景示例：电商运营管理系统

假设 Agent 应用里挂了一个「电商运营管理系统」——原先只负责商品、订单、营销与经营数据。

| 场景 | 用户在业务界面里做什么 | EvoFlow 侧 |
|------|------------------------|------------|
| **A 工作流** | 点「生成商品上架方案」 | 触发预设工作流；界面可看步骤进度与最终结果 |
| **B AI 员工** | 与「电商运营 AI 员工」对话，或派发任务 | 例如分析近 7 天表现差的商品并给优化建议；可回看进度与交付 |
| **C 知识库** | 查询商品资料、运营 SOP、历史经验 | 问答、辅助决策、内容生成时带上企业知识 |

用户无需在多个平台之间来回切换，即可在原业务界面使用平台 AI 能力。

## 6. F4 功能架构图怎么画

主体分三块 + 底部价值条：

| 区域 | 内容 |
|------|------|
| **左侧** | 多类型应用接入：静态网页、服务器应用、本地服务、第三方业务系统 |
| **中间** | Agent 应用中心：应用管理、应用访问、网页承载、集成配置、运行管理（含统一应用列表、平台内打开） |
| **右侧** | EvoFlow AI 底座：工作流 / AI 员工 / 知识库，各展示调用方式、执行状态、结果反馈 |
| **底部** | 业务价值：存量系统智能化 · 统一应用入口 · AI 能力复用 · 业务执行闭环 |

## 7. 和相近概念的区分

| 概念 | 是什么 | 不是 |
|------|--------|------|
| **Agent 应用**（`#/extensions`） | 业务网页 / 系统的承载与 AI 连接入口 | 不是「工作流」产品页 |
| **工作流**（旧名「应用中心」，`#/apps`） | 多节点流程编排 → 发布 → 填参再跑 | 不是侧栏挂网页 |
| **插件市场** | 能力包（技能、命令等）安装启停 | 不是业务系统承载 |
| **智能体** | 「会什么」的能力包配置 | 不是业务应用列表 |
