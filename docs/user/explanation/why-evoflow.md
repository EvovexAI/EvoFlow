# 为什么是 EvoFlow

> **简单说**：多数 AI 工具擅长「聊几句」或「写一段代码」；EvoFlow 要解决的是——**把一件多步的事做完，并且可规划、可审批、可观测、可沉淀、可再跑**。
>
> - **聊天产品**：问一句答一句，长任务易跑偏，没有任务看板与验收。
> - **编码 CLI / IDE Agent**：写码深，但不主打岗位值班、多节点业务工作流、组织审批。
> - **纯 harness / 助手网关**：能编排 Agent，但往往缺桌面控制平面上的「排班表、费用账、安全闸门、资源市场」。
> - **EvoFlow**：桌面控制平面 + Agent Runtime——Plan / Goal、应用中心、智能体员工、资产自我进化、费用与运维，开箱即用。
>
> 读完应能回答：它突出什么、适合哪两类用法、和「只聊天 / 只写码」差在哪。功能怎么点见 [产品总览](../getting-started/product-overview.md)；和 DF / 爱马仕 / Codex / 小龙虾对照见 [生态对照](ecosystem-comparison.md)。

本文回答 **「为什么做成这样」**——先讲产品主叙事与突出能力，再补架构边界与工程原则（给扩展开发者）。

---

## 1. 产品一句话

EvoFlow = **原生 Agent Runtime**（规划、委派、工具、沙箱、恢复）+ **产品控制平面**（对话壳、任务、岗位、工作流、治理、扩展）。

不是「又一个聊天窗」，也不是「只给开发者的 harness 说明书」——而是让个人与小团队把长任务与固定业务**跑在可验收的车间里**。

---

## 2. 两条主打场景（先记住这个）

| 场景 | 你要什么 | EvoFlow 怎么接 |
|------|----------|----------------|
| **个人固定业务工作流** | 同一套多节点流程反复跑，只换参数 | **应用中心**编排并发布 → 填参再跑；可叠加**自动化**到点触发；过程进**任务中心** |
| **组织协作：多 AI 员工** | 多个岗位并行，关键环节人把关 | **智能体**配能力 → **智能体员工**值班/委派 → **关键审批 / 验收**；小V 临时派活；汇报与总结可落盘 |

一句话：**固定流程产品化；多人（多员工）加闸门；跑完还能沉淀经验与反思。**

---

## 3. 突出能力（按控制平面心智）

下面这些是产品**一等公民**——不是边角配置。完整入口树见 [生态对照 · 功能地图](ecosystem-comparison.md#3-evoflow-功能地图当前活动项目) 与 [产品总览](../getting-started/product-overview.md)。

### 3.1 把事做完：Plan / Goal / Teams / 任务中心

| 能力 | 突出点 |
|------|--------|
| **Plan** | 先澄清、出可修订计划，你确认后再执行——复杂事少「瞎干」 |
| **Goal** | 长任务后台自驱，少盯屏 |
| **Agent Teams / 项目团队** | 多 Agent 隔离上下文、委派、可插手与重试 |
| **任务中心** | 看板、DAG、任务总结与验收——执行层可见、可打回 |

### 3.2 固定业务：应用中心 + 自动化

| 能力 | 突出点 |
|------|--------|
| **应用中心** | 多节点协作工作流：画布编排 → 发布 → ▶ 填参再跑（个人业务流水线） |
| **自动化** | 到点 / 一次性固定 Prompt；可推 IM |

### 3.3 组织形态：智能体员工 + 关键审批

| 能力 | 突出点 |
|------|--------|
| **智能体** | 人设、工具、技能、MCP——「会什么」 |
| **智能体员工** | 值班、职责、管辖工作区、**关键审批**、工作汇报——「何时干、谁放行」 |
| **小V** | 前台临时委派，不必改岗位职责 |

### 3.4 工程上下文：工作空间 + 代码索引

| 能力 | 突出点 |
|------|--------|
| **工作空间** | 本机项目目录绑定、侧栏分组、读写边界（和沙箱策略叠加） |
| **代码索引** | 导入 / 引用 / 类型图谱；Agent 可 `search_code_index`——不只全文搜 |

### 3.5 自我进化：资产中心

| 能力 | 突出点 |
|------|--------|
| **画像 / 记忆** | 跨会话记得偏好与约定 |
| **经验沉淀** | 把「怎么做」固化下来，下次少从头教 |
| **反思过程** | 日结 / 判断记录，形成可回顾的进化轨迹 |

对话里也可直接说「记住 / 沉淀 / 反思」落到资产中心。

### 3.6 治理套件：多账号 · 费用 · 观测 · 安全

| 能力 | 突出点 |
|------|--------|
| **多账号体系** | 用户权限 / ACL、企业 SSO；IM 渠道多账号 |
| **费用统计** | Token 与费用账本（按日 / 模型拆分）；员工侧也可见成本 |
| **运维观测** | 会话时间线、工具 / 模型、Gateway 热点（`#/observability`） |
| **安全中心** | OS 沙箱、默认权限、终端策略、审计——高风险能力有闸 |

### 3.7 扩展与触达：资源市场 · 技能 · MCP · IM

| 能力 | 突出点 |
|------|--------|
| **资源中心 / 资源市场** | 资源包与扩展应用安装、本机清单 |
| **技能 + MCP** | `SKILL.md` 能力包与外部连接器 |
| **IM 渠道** | 飞书 / 微信 / Slack / Telegram 等与桌面同一线程心智 |
| **多模型** | 设置里配服务商与主模型，开箱改 |

### 3.8 底座（常被当成「全部」，其实是支撑）

沙箱执行、Supervisor / 子代理、记忆中间件、场景化工具暴露——这些保证上面能力**真能跑**；但对外叙事优先是 **Plan→验收、工作流、员工审批、自我进化、治理**，而不是「又一个 LangGraph demo」。

## 5. 四层架构（为什么能撑住上面这些）

依赖单向：上层依赖下层，下层不感知上层。

```
┌──────────────────────────────────────┐
│  EvoPanel（桌面 / Web）               │   控制平面：对话、任务、员工、设置…
└──────────────────────────────────────┘
                ▲ REST / SSE / WebSocket
┌──────────────────────────────────────┐
│  Gateway（FastAPI）                   │   模型、记忆、技能、MCP、文件、渠道、观测…
└──────────────────────────────────────┘
        ▲                       ▲
┌──────────────────┐   ┌───────────────────┐
│  LangGraph 运行时 │   │  Channels（IM）    │
└──────────────────┘   └───────────────────┘
                ▲
┌──────────────────────────────────────┐
│  Harness（evoflow.*）                 │   工具、技能、记忆、子代理、沙箱、Supervisor
└──────────────────────────────────────┘
```

| 层 | 角色 |
|----|------|
| **EvoPanel** | 产品 GUI：你感知到的几乎全部「突出功能」入口 |
| **Gateway** | 产品级 API 与业务聚合 |
| **Channels / App** | IM、自动化等业务挂载 |
| **Harness** | 与产品壳解耦的 Agent 框架，可独立演进 |

**边界**：Harness 不引用 App；App 不引用桌面工程目录。渠道、路由、组织能力在上层长；框架内核保持稳定。

## 6. 五条工程原则（支撑体验，不是卖点清单）

### 1. Harness / App 分离

`evoflow.*`：工具、技能、子代理、Supervisor、沙箱、记忆、护栏。  
`app.*`：渠道、自动化、存储、偏好、产品 API。  
→ 可嵌 harness；行业定制改上层。

### 2. 线程隔离与原子写入

会话数据按线程目录切分；关键文件临时写入再 rename，避免半写入。

### 3. 懒初始化

MCP、沙箱、模型客户端等按需拉起——冷启动稳、闲置能力不占坑。

### 4. 配置热更新

Agent / 技能 / MCP / 自动化等改完按 mtime 生效，少重启。

### 5. 工具按场景渐进暴露

日常对话只给核心工具；进入工作空间 / Plan 等场景再暴露文件、终端、supervisor——控 Token，也控风险。
