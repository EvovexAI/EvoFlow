# 智能体员工

> **智能体员工就是让 AI 从「你问它答」变成「主动上班干活」。**
>
> ---
>
> **场景一：你有一个「服务器巡检」的固定需求**
>
> 你需要每天检查 3 个服务（gateway、langgraph、postgres）是否健康，有异常就告警，正常就写个巡检报告。
>
> **以前**：每天手动登录服务器，敲命令检查，写报告……重复劳动。
>
> **用智能体员工**：
> 1. 先在「**智能体**」页创建或选一个角色，比如「运维助手」——给它配好 terminal 工具和飞书推送权限
> 2. 到「**智能体员工**」页，点「雇佣员工」
> 3. 配置：
>    - **岗位名称**：服务器巡检
>    - **职责**：每 30 分钟检查一次 gateway/langgraph/postgres 的健康状态，异常时推送飞书告警，下班前写巡检报告
>    - **管辖工作空间**：选一个目录，报告会写到那里
>    - **交接审批策略**：选「谨慎型」——所有事项先问你再做（推荐上手）
>    - **上岗节奏**：每 30 分钟
>    - **上班时间**：09:00–20:00
> 4. 点「确认上岗」
>
> **之后每天**：
> - 09:00：员工自动上岗，开始巡检
> - 09:30：第一轮完成，报告写到工作空间
> - 遇到异常：员工先暂停，给你发「待审批」——你同意告警，它才推飞书
> - 20:00：写交班报告，下班
>
> 你只需要在「**待审批**」Tab 里看看有没有事项，同意或驳回即可。
>
> ---
>
> **场景二：你家有个「代码审查员」**
>
> 你有一个「代码审查」角色，专门做 PR 审查。你把它雇成员工：
> - **职责**：每 2 小时检查一次项目仓库的新提交，执行代码审查，输出审查意见
> - **交接审批策略**：选「平衡型」——常规审查自动完成，遇到重大设计问题才问你
>
> 它会在后台自动审查代码，审查结果写到工作空间；交工后你在工作项详情或 [任务中心](../tasks/task-center.md) 看 **任务总结** 再验收。
>
> ---
>
> **场景三：临时委派，不必改职责**
>
> 今天突然要让「产品运营」岗写一版对外更新说明。不必改岗位职责、也不必等下一次心跳：打开全局助手 **小V** → 左侧点选该员工 → 输入目标。会话里看进度与汇报，需要时再打开 **工作轨迹**。
>
> ---
>
> **智能体员工 vs 自动化的核心区别：**
>
> | 维度 | 自动化 | 智能体员工 |
> |------|--------|-----------|
> | 本质 | 到点跑一条固定 prompt | 一个有职责、有审批、有交班的岗位 |
> | 灵活度 | 每次都执行同样的指令 | 每次根据工作区当前状态自主决策 |
> | 审批 | 无 | 开工前审批、交工后验收、交接派发可再批 |
> | 交班 | 无 | 写交班报告、记录工作轨迹 |
> | 组织关系 | 无 | 有部门、上下级、看板 |
>
> **一句话总结**：自动化是「到点跑固定脚本」，员工是「雇了个 AI 员工上班」。
>
> 侧栏入口：**智能体员工**（`#/proactive`）。  
> 概念说明见 [智能体员工是什么](../../explanation/smart-employees.md)；逐步上手见 [雇佣第一个员工](../../tutorials/hire-first-smart-employee.md)。

让已有**智能体**按岗位定时上岗：巡检工作区、建工作项、等你拍板、交班写报告。侧栏入口：**智能体员工**（`#/proactive`）。

> **和「智能体」页不是一回事**  
> - **智能体**（`#/expert`）：配置人设、工具、技能——「会什么」  
> - **智能体员工**：给智能体加岗位合同（职责、工作区、心跳、审批）——「什么时候主动干、干到哪」  
> 雇佣前须先在「智能体」页有对应 Agent（可用 [预设角色](../chat/preset-roles.md) 或 [自行创建](agent-management.md)）。

帮助面板：雇佣岗位 → 配置职责 → 开值班 / 用小V 委派 → 审批与验收。

> **怎么工作？多岗什么关系？** 见概念文 [智能体员工是什么](../../explanation/smart-employees.md)（单岗心跳、组织树、交工下游、并行同事、能干嘛）。

## 前置条件

1. 已配置可用对话模型（侧栏「模型配置」）
2. 「智能体」页已有目标 Agent（工具权限要够：读写工作区、需要时 terminal / 飞书等）
3. 对话侧栏已添加本机**工作空间**目录（雇佣时要从历史里选「管辖工作空间」）
4. （可选）[飞书集成](../integration/feishu-integration.md)：扫码绑定专属飞书后，审批与交班可推到对应账号
5. （可选）Premium / 授权：侧栏无入口或提示授权时，按许可证说明处理

全局值班由面板「值班台」开关控制；若引擎被环境关闭（如 `EVOFLOW_PROACTIVE_SCHEDULER=0`），页面会提示无法连接值班服务。

## 5 分钟上手

1. 侧栏点 **智能体员工**
2. 值班台点 **开启值班**（状态变为「全员值班中」）
3. 点 **雇佣员工**，填写：
   - **选择智能体**：选已有 `agent_code`
   - **岗位名称**、**职责**（每行一条）
   - **管辖工作空间**（必选）
   - **交接审批策略**：建议先选 **谨慎型**（所有事项须你同意）
   - **上岗节奏**：如每 30 分钟 / 每小时
4. 点 **确认上岗**（也可先「保存草稿」）
5. 等下一次心跳，或卡片菜单点 **立即开工**（不受上班时间限制）
6. 有事项时到 **待审批** Tab：`Y` 同意 · `N` 驳回 · `J` 下一条

也可在「智能体」页对某角色点 **雇佣** / **值班台**，跳到同一套流程。

临时委派不必等心跳：打开全局助手 **小V**，左侧点选该员工后输入目标即可（见 [用小V 委派与开会](#用小v-委派与开会)）。

更细的逐步教程：[雇佣第一个智能体员工](../../tutorials/hire-first-smart-employee.md)。

## 主界面导览

页头文案：**数字员工 · 智能体员工**——有事项等你拍板时优先处理；员工近况看「员工」，进度全貌看「工作项」。

| 区域 / Tab | 作用 |
|------------|------|
| **值班台** | 全局 **开启值班** / **结束值班**；显示在岗人数与待批数 |
| **待审批** | 开工前拍板、以及跨岗 **交接审批**（同意派发） |
| **员工** | 名册卡片：状态、近况、⋯ 菜单操作 |
| **工作项** | 跳转全员看板 `#/proactive/board` |
| **组织架构** | 按部门 / 上下级看编制，可改直属上级 |
| **健康** | 今日成本、卡住执行、疑似空转、预算告警等 |
| **归档** | 已归档员工；可重新上岗或彻底删除 |

### 常用路由

| 路由 | 页面 |
|------|------|
| `#/proactive` | 控制台 |
| `#/proactive/board` | 岗位工作项看板（可 `?role=<code>&hideDone=1`） |
| `#/proactive/:code` | 该员工工作日志 |
| `#/proactive/:code/work/:taskId` | 单个工作项详情（交工验收常在这里） |
| `#/proactive/:code/item/:itemId` | 单个事项详情（审批 / 轮次） |

### 员工卡片上常见状态

| 徽章 | 含义 |
|------|------|
| **工作中** | 本轮正在跑 |
| **上班中** | 参与心跳、可自动上岗 |
| **休息中** | 上班时间窗外等（不自动心跳；立即开工仍可） |
| **摸鱼中** / **摸鱼中×N** | 连续多轮无明显产出或空转信号偏高——优先看 [健康](#健康与摸鱼) 与工作轨迹 |
| **已请假** | 暂停自动上岗 |
| **草稿** | 未确认上岗 |
| **已归档** | 不在名册、不自动上班 |
| **N 待批** | 该岗有待你处理的审批 |
| **系统前台** | 安装自带岗，偏催办全局待办（勿当普通业务岗乱改删） |

点卡片「近况」或进工作日志，可看最近一轮在干什么。

## 雇佣与编辑字段

「雇佣上岗」与「编辑岗位」共用大部分字段；**工作方式（深度 / 轻量）** 常见于编辑岗。

| UI 标签 | 说明 |
|---------|------|
| **选择智能体** / **绑定智能体** | 底层 Agent；人设/工具仍回「智能体」页改；编辑时一般可改绑 |
| **岗位名称** | 展示名 |
| **职责** | 每行一条；决定巡检时优先想什么——写具体、可验收，少写空话 |
| **管辖工作空间** | 本机目录；方案/报告会写到该工作空间下 |
| **绑定知识库** | 可多选 Knowledge Vault；值班系统提示会注入绑定列表，员工应优先用 `knowledge` 检索 |
| **关注子路径** | 相对工作空间的子目录，缩小巡检范围 |
| **部门** / **直属上级** | 组织关系（更多设置）；影响催办与上下级视图 |
| **工作/执行模型** | 空 = 跟随智能体默认模型 |
| **交接审批策略** | 见下表（界面文案；口语里有时也称「自主权」） |
| **上岗节奏** | 心跳 RRULE：10/30 分钟、1/2/3 小时、每天 9:00 等 |
| **上班时间** | 可启用；窗外一般不自动心跳（**立即开工**仍可） |
| **工作方式** | **深度工作**（可调工具的 agent loop）/ **轻量工作**（单次 LLM，省成本但能力弱） |

### 交接审批策略三档

| 芯片文案 | 含义 |
|----------|------|
| **全自动** | 仅极高风险须你同意；其余自动执行 |
| **平衡型** | 中风险及以上须你同意；低风险可自动（常见默认） |
| **谨慎型** | 所有事项须你同意后才执行（推荐上手） |

上手建议：先 **谨慎型** + 较短节奏（如 30 分钟）+ **立即开工** 试一轮，确认工具与工作区正常后，再放宽策略或拉长节奏。

### 岗位状态（编制）

| 标签 | 含义 |
|------|------|
| **上班中** | 参与心跳与值班 |
| **已请假** | 暂停自动上岗 |
| **草稿** | 未确认上岗；可「确认上岗」 |
| **已归档** | 不出现在名册、不自动上班；历史保留 |

## 日常操作

| 操作 | 说明 |
|------|------|
| **立即开工** | 手动触发一轮值班心跳；可勾选「本轮事项」聚焦某一项 |
| **派发任务** | 填写任务目标 / 补充说明 / 优先级，派给该岗；打开工作轨迹跟进 |
| **小V 委派** | 全局助手左侧选员工，聊天下发临时目标 |
| **请假** / **上班** | 暂停或恢复自动心跳（请假时可能中止本轮） |
| **编辑岗位** | 改职责、节奏、工作区、交接审批策略、工作方式等 |
| **扫码绑定飞书** / **解绑** | 该岗专属飞书机器人（与小V 均可绑） |
| **工作轨迹** | 查看本轮工具与对话（按需打开） |
| **继续本轮** | 在工作项详情上，对未闭环轮次接着干 |
| **归档** | 离开名册；可在「归档」Tab **重新上岗** |
| **删除岗位** | 去掉岗位编制（底层智能体仍在「智能体」页） |

同一员工若已有一轮在跑，再点开工会提示稍候。

### 待审批怎么点

| 按钮 | 何时出现 | 作用 |
|------|----------|------|
| **同意** | 普通事项审批 | 放行开工 / 执行 |
| **同意派发** | 芯片标「交接审批」的跨岗交接 | 同意把工作派给下游岗 |
| **驳回** | 均有 | 须填原因 |
| **关闭无效项** / **丢弃** | 孤儿或无效项 | 清掉卡住的脏数据 |

快捷键（待审批列表）：`Y` 同意 · `N` 驳回 · `J` 下一条。

## 用小V 委派与开会

全局助手 **小V** 是员工模块的「遥控器」：临时委派、看进度、开会、绑飞书，不必只在 `#/proactive` 里点菜单。

### 对话：一员工一会话

1. 打开 **小V**
2. 切到 **对话** Tab；左侧联系人列表点选某员工（可悬停展开）
3. 在右侧对该员工直接输入目标并发送
4. 会话内可看进行中任务与最新汇报；历史完成默认折叠，最新在下
5. 需要工具级细节时再点开 **工作轨迹**（默认不打扰主视图）
6. 可用「请求进度」等快捷，或进该员工详情 / 工作日志

也可先对小V 本人聊天（调度建议、今日汇报等），再切到具体员工会话委派。值班派发可续用同一轮工作轨迹，便于在原任务上继续推进。

### 工作台

**工作台** Tab 汇总今日概览：需要关注、正在执行、刚刚完成、建议推进；常见快捷包括今日汇报、员工进度、待推进、待我审批、问知识库、委派任务。适合早上打开扫一眼。

### 会议

在小V **会议** Tab：**发起讨论** / 停止。输入讨论话题后可让员工参会讨论（当前产品以全员参会讨论为主）。适合跨岗对齐议题；复杂选人、轮次编排若界面未提供，用「派发任务」或逐岗委派即可。

### 飞书

员工页或小V 内 **扫码绑定飞书** / 解绑；渠道页可查看岗位绑定关系。详见 [飞书集成](../integration/feishu-integration.md)。

## 工作项看板

入口：控制台 **工作项** Tab → `#/proactive/board`。

| 列 | 含义 |
|----|------|
| **待办** | 已建项、尚未执行 |
| **执行中** | 员工正在处理 |
| **已完成** | 闭环 |
| **失败** | 执行失败或未完成交班等 |

可按员工筛选、**隐藏已完成**。卡片可删除；标「有上游」表示来自下游接力链。

> **验收不在看板列上单独叫「待确认」**  
> 交工后的验收主要在：**工作项详情**（状态如「待你验收 / 交工待验收」）以及 [任务中心](../tasks/task-center.md) 的「待确认」与 **任务总结**。看板用来扫进度与失败项。

### 待审批 vs 交工验收

| | **待审批**（控制台 Tab） | **交工验收**（工作项详情 / 任务中心） |
|--|--------------------------|----------------------------------------|
| 时机 | **开工前**拍板，或 **交接派发**前同意 | **交工后**验收 |
| 动作 | 同意 / 同意派发 / 驳回 | 确认完成 / 打回重做 |
| 超时 | 超时项显示为「审批超时」 | — |

不要把「交工验收」当成「同意执行」——前者是收工验收，后者是放行开工或放行派发。

## 交工、任务总结与下游接力

### 交工时你会看到什么

员工交工提审后，在 `#/proactive/:code/work/:taskId` 常见：

- 状态：**待你验收** / **交工待验收**
- **完成结果**、**本岗交付物**、**关键发现**、**建议下一步**
- 若有上游：**上游参考产物**
- **查看完整总结** / **任务总结**（做了什么、交付了什么、如何验收）

你在此 **确认完成** 或 **打回重做**；也可用 **工作轨迹**、**继续本轮**，或从 ⋯ 打开 [任务中心](../tasks/task-center.md) 详情。

任务中心「智能体员工」来源 Tab 的列表与详情也会展示任务总结，便于跨岗统一验收。

### 下游接力

交工时可指定 **谁继续处理、读哪些产物**。下游接到后：

1. 可能产生带「交接审批」芯片的待批项 → 你点 **同意派发**
2. 下游工作项可看到上游参考产物与「有上游」标记
3. 整条链在任务中心仍可按根单聚合查看

适合：调研岗交分析稿 → 写作岗出对外稿；开发岗交实现 → 测试岗验收。

## 工作日志与交班

进入 `#/proactive/:code` 可看：

- 岗位信息：交接审批策略、飞书、**值班记忆**、**成本（近 7 日）**、系统前台等
- 值班轮次与工作记录（可按日筛）
- 轮次阶段文案：开工记录 → 中途记录 → **本轮小结**（wrap_up）
- 每轮可打开 **工作轨迹**
- 顶栏：**立即开工**、编辑岗位、绑飞书、归档等

### 自动交班未完成

若出现 **自动交班·未完成** / **【交班汇报·未完成】**：

1. 打开该轮 **工作轨迹**，看是否中途中断、超时或未调用交班
2. 可再点 **立即开工**（或工作项上 **继续本轮**）；不要只改职责文案碰运气
3. 交付文档是否落盘见下一节
4. 同时看 [健康](#健康与摸鱼) 是否有卡住执行 / 疑似空转

## 交付文档写在哪

方案 / 报告 / 纪要类 Markdown 写到工作空间下：

```text
docs/roles/<agent_code>/<YYYYMMDD-HH>/…
```

- `<agent_code>`：绑定的智能体代码（不是岗位显示名）
- `<YYYYMMDD-HH>`：UTC 小时桶，避免互相覆盖
- 对话里可用 `@@docs/roles/…/某文件.md@@` 引用

约定说明见仓库 `docs/roles/README.md`（产出知识库根）。稳定的操作说明应沉淀进 `docs/user/`，不要把值班产出当产品文档 SSOT。

## 组织架构

**组织架构** Tab：树形查看部门与上下级；可 **全部展开**、刷新，调整某岗的 **直属上级**，查看直属下级并打开其工作轨迹。

用途：催办与「谁管谁」视图——这是**编制关系**，不会自动把活拆给下级。多岗真正一起交付，靠 [交工下游接力](#交工任务总结与下游接力)。

**想看上下级 + 同级怎么转一天**：概念文有完整故事——[整套体系举例](../../explanation/smart-employees.md#整套体系举例上下级--同级怎么转起来)（技术总监 / 前后端同级 / 交工给测试）。

## 健康与摸鱼

**健康** Tab（及卡片上的「摸鱼中」）帮你判断「在跑但没产出」还是真的在干活：

| 信号 | 建议 |
|------|------|
| **摸鱼中** / 连续空转 | 打开工作轨迹看是否被审批卡住、工具失败、职责太空 |
| **卡住执行** | 执行超过约 45 分钟仍未结束的事项；尝试结束异常轮或再立即开工 |
| **今日成本 / 预算告警** | 节奏过密或深度工作过重时收紧节奏 / 改轻量工作 |
| **在岗但待批堆高** | 先去待审批清掉阻塞，再谈职责 |

排查清单也见 [FAQ：员工没产出](../faq.md#问题智能体员工没产出--交班未完成)。

## 和其它能力怎么选

| 场景 | 更合适 |
|------|--------|
| 跟人多轮聊、临时探索 | 实时聊天 + 切换智能体 |
| 临时把目标派给某岗、看进度汇报 | **小V 委派**（本文） |
| 一次大型多角色软件交付 | [Plan 模式](../chat/plan-mode.md) / [任务中心](../tasks/task-center.md) |
| 到点重复跑固定 prompt | [自动化](../tasks/scheduled-tasks.md) |
| 流程已固定、只换参数再跑 | [应用中心](app-center.md) |
| 长期盯仓库/项目、主动巡检与交班 | **智能体员工**（本文） |

值班路径默认不走聊天里的 Supervisor 大图拆派；员工在自己的岗位会话里干活（`proactive:{agent_code}`）。小V 对员工的会话与岗位会话对齐，便于委派与跟进。

## 常见问题

**Q：侧栏没有「智能体员工」？**  
确认客户端版本包含该入口；入口在聊天壳侧栏，文案为「智能体员工」。若提示 Premium / 授权相关，按许可证说明处理。

**Q：雇佣时选不到工作空间？**  
先在聊天侧栏添加本机工作区目录，再回来雇佣。

**Q：心跳在跳但事项全是失败 / 交班未完成？**  
说明岗在跑、交班没闭环。打开该员工工作轨迹看最后一轮工具与小结；也可在小V 员工会话里按需打开工作轨迹。优先查超时、上班时间窗外、工作区权限、待审批是否堆着，而不是先改职责文案。

**Q：卡片一直显示「摸鱼中」？**  
看健康 Tab 与近几轮工作轨迹：是否无工具调用、是否一直在等审批、职责是否无法落地。试一次「立即开工」并收紧职责表述。

**Q：交工后去哪验收？**  
工作项详情的交工待验收，或 [任务中心](../tasks/task-center.md) 打开该任务，先看 **任务总结**，再确认完成或打回。

**Q：交接审批和普通同意有何区别？**  
普通 **同意** 放行本岗事项；**同意派发** 放行跨岗下游交接。待审批列表里有「交接审批」芯片时用后者。

**Q：和「自动化」有何区别？**  
自动化是按 Cron 跑固定任务提示词；智能体员工是编内岗位：有职责、看板、审批、组织关系与交班文档。

**Q：改了智能体的 SOUL，员工会变吗？**  
会。岗位绑定的是同一 `agent_code`；人设与工具以「智能体」页为准，岗位页只管职责/节奏/工作区/审批策略。

**Q：归档后历史还在吗？**  
在。归档岗不自动上班、不在名册；可在「归档」Tab 重新上岗。彻底删除岗位不会删除「智能体」页里的 Agent 定义。
