# 智能体员工

> **智能体员工就是让 AI 从「你问它答」变成「主动上班干活」。**
>
> ---
>
> **场景一：你有一个「运维值班」的固定需求**
>
> 你需要每天检查 3 个服务（gateway、langgraph、postgres）是否健康，有异常就告警，正常就写个值班报告。
>
> **以前**：每天手动登录服务器，敲命令检查，写报告……重复劳动。
>
> **用智能体员工**：
> 1. 先在「**智能体**」页创建或选一个角色，比如「运维助手」——给它配好 terminal 工具和飞书推送权限
> 2. 到「**智能体员工**」页，点「雇佣员工」
> 3. 配置：
>    - **岗位名称**：运维值班
>    - **职责**：每 30 分钟检查一次 gateway/langgraph/postgres 的健康状态，异常时推送飞书告警，下班前写值班报告
>    - **管辖工作空间**：选一个目录，报告会写到那里
>    - **交接审批策略**：选「谨慎型」——交工带下游时几乎都要「同意派发」（推荐上手）
>    - **上班频率**：每 30 分钟
>    - **上班时间**：09:00–20:00
> 4. 点「确认上班」
>
> **之后每天**：
> - 09:00：员工自动上班，开始检查服务（新任务默认直接跑）
> - 09:30：第一轮完成，报告写到工作空间
> - 遇到需批事项：待审批里点 **同意**（少见）；有下游交工时点 **同意派发**
> - 交工验收：工作项详情 / 任务中心看 **任务总结**，确认或打回
> - 20:00：写工作汇报，下班
>
> 日常扫一眼待审批；有交工再去任务中心验收。
>
> ---
>
> **场景二：你家有个「代码审查员」**
>
> 你有一个「代码审查」角色，专门做 PR 审查。你把它雇成员工：
> - **职责**：每 2 小时检查一次项目仓库的新提交，执行代码审查，输出审查意见
> - **交接审批策略**：选「平衡型」——交工带下游时中风险以上才「同意派发」
>
> 它会在后台自动审查代码，审查结果写到工作空间；交工后你在工作项详情或 [任务中心](../tasks/task-center.md) 看 **任务总结** 再验收。
>
> ---
>
> **场景三：临时委派，不必改职责**
>
> 今天突然要让「产品运营」岗写一版对外更新说明。不必改岗位职责、也不必等下一次心跳：打开全局助手 **小V** → 左侧点选该员工 → 输入目标。会话里看进度与汇报，需要时再打开 **工作轨迹**。
>
> ---
>
> **智能体员工 vs 自动化的核心区别：**
>
> | 维度 | 自动化 | 智能体员工 |
> |------|--------|-----------|
> | 本质 | 到点跑一条固定 prompt | 一个有职责、有审批、有工作汇报的岗位 |
> | 灵活度 | 每次都执行同样的指令 | 每次根据工作区当前状态自主决策 |
> | 审批 | 无 | 主闸在交工后「同意派发」；另有交工验收；事项「同意」少见 |
> | 工作汇报 | 无 | 写工作汇报、记录工作过程 |
> | 组织关系 | 无 | 有部门、上下级、看板 |
>
> **一句话总结**：自动化是「到点跑固定脚本」，员工是「雇了个 AI 员工上班」。
>
> 侧栏入口：**智能体员工**（`#/proactive`）。  
> 概念说明见 [智能体员工是什么](../../explanation/smart-employees.md)；逐步上手见 [雇佣第一个员工](../../tutorials/hire-first-smart-employee.md)。

让已有**智能体**按岗位定时上班：盯工作区、建工作项、按需审批与验收、下班写工作汇报。侧栏入口：**智能体员工**（`#/proactive`）。

> **和「智能体」页不是一回事**  
> - **智能体**（`#/expert`）：配置人设、工具、技能——「会什么」  
> - **智能体员工**：给智能体加岗位合同（职责、工作区、心跳、审批）——「什么时候主动干、干到哪」  
> 雇佣前须先在「智能体」页有对应 Agent（可用 [预设角色](../chat/preset-roles.md) 或 [自行创建](agent-management.md)）。

帮助面板：雇佣岗位 → 配置职责 → 开值班 / 用小V 委派 → 审批与验收。

> **怎么工作？多岗什么关系？入口与状态？** 见概念文 [智能体员工是什么](../../explanation/smart-employees.md)（两条通道、入口一览、状态流转、下游形式、何时审核）。  
> **谁在用？组织怎么配？怎么协作？** 见专文 [组织与协作玩法](../../cases/smart-employee-playbooks.md)（八类画像，含组织树与一天故事）。

## 前置条件

1. 已配置可用对话模型（侧栏「模型配置」）
2. 「智能体」页已有目标 Agent（工具权限要够：读写工作区、需要时 terminal / 飞书等）
3. 对话侧栏已添加本机**工作空间**目录（雇佣时要从历史里选「管辖工作空间」）
4. （可选）[飞书集成](../integration/feishu-integration.md)：扫码绑定专属飞书后，审批与工作汇报可推到对应账号
5. （可选）Premium / 授权：侧栏无入口或提示授权时，按许可证说明处理

全局值班由面板「值班台」开关控制；若引擎被环境关闭（如 `EVOFLOW_PROACTIVE_SCHEDULER=0`），页面会提示无法连接值班服务。

## 5 分钟上手

1. 侧栏点 **智能体员工**
2. 值班台点 **开启自动上班**（状态变为「全员值班中」）
3. 点 **雇佣员工**，填写：
   - **选择智能体**：选已有 `agent_code`
   - **岗位名称**、**职责**（每行一条）
   - **管辖工作空间**（必选）
   - **交接审批策略**：建议先选 **谨慎型**（交工下游几乎都要「同意派发」）
   - **上班频率**：如每 30 分钟 / 每小时
4. 点 **确认上班**（也可先「保存草稿」）
5. 等下一次心跳，或卡片菜单点 **现在开始工作**（不受上班时间限制）
6. 有待审批时：交接芯片用 **同意派发**，否则用 **同意**（`Y` / `N` / `J`）

也可在「智能体」页对某角色点 **雇佣** / **值班台**，跳到同一套流程。

临时委派不必等心跳：打开全局助手 **小V**，左侧点选该员工后输入目标即可（见 [用小V 委派](#用小v-委派)）。

更细的逐步教程：[雇佣第一个智能体员工](../../tutorials/hire-first-smart-employee.md)。

## 主界面导览

页头文案：**数字员工 · 智能体员工**——待审批优先清（尤其是同意派发）；员工近况看「员工」，进度全貌看「工作项」。

| 区域 / Tab | 作用 |
|------------|------|
| **值班台** | 全局 **开启自动上班** / **结束值班**；显示在岗人数与待批数 |
| **待审批** | 交接 **同意派发**（主路径），以及少数事项 **同意** |
| **员工** | 名册卡片：状态、近况、⋯ 菜单操作 |
| **工作项** | 跳转全员看板 `#/proactive/board` |
| **组织架构** | 按部门 / 上下级看编制，可改直属上级 |
| **健康** | 今日成本、卡住执行、疑似空转、预算告警等 |
| **归档** | 已归档员工；可重新上岗或彻底删除 |

### 常用路由

| 路由 | 页面 |
|------|------|
| `#/proactive` | 控制台 |
| `#/proactive/board` | 岗位工作项看板（可 `?role=<code>&hideDone=1`） |
| `#/proactive/:code` | 该员工工作日志 |
| `#/proactive/:code/work/:taskId` | 单个工作项详情（交工验收常在这里） |
| `#/proactive/:code/item/:itemId` | 单个事项详情（审批 / 轮次） |

### 员工卡片上常见状态

| 徽章 | 含义 |
|------|------|
| **工作中** | 本轮正在跑 |
| **上班中** | 参与心跳、可自动上班 |
| **休息中** | 上班时间窗外等（不自动心跳；现在开始工作仍可） |
| **摸鱼中** / **摸鱼中×N** | 连续多轮无明显产出或空转信号偏高——优先看 [健康](#健康与摸鱼) 与工作轨迹 |
| **已请假** | 暂停自动上班 |
| **草稿** | 未确认上班 |
| **已归档** | 不在名册、不自动上班 |
| **N 待批** | 该岗有待你处理的审批 |
| **系统前台** | 安装自带岗，偏催办全局待办（勿当普通业务岗乱改删） |

点卡片「近况」或进工作日志，默认可看**近 2 天**上岗记录；更早用「本岗全部任务」进任务中心筛选。

## 雇佣与编辑字段

「雇佣员工」与「编辑岗位」共用大部分字段；**工作方式（深度 / 轻量）** 常见于编辑岗。

| UI 标签 | 说明 |
|---------|------|
| **选择智能体** / **绑定智能体** | 底层 Agent；人设/工具仍回「智能体」页改；编辑时一般可改绑 |
| **岗位名称** | 展示名（写成真实职称更好，如「研发助理」「运维值班」） |
| **职责** | 每行一条；决定上班时优先想什么——写具体、可验收，少写空话 |
| **管辖工作空间** | 本机目录；方案/报告会写到该工作空间下（须先在聊天侧栏添加） |
| **绑定知识库** | 可多选 Knowledge Vault；值班系统提示会注入绑定列表，员工应优先用 `knowledge` 检索 |
| **关注子路径** | 相对工作空间的子目录，缩小盯盘范围 |
| **部门** / **直属上级** | 组织关系（更多设置）；影响催办与上下级视图 |
| **工作/执行模型** | 空 = 跟随智能体默认模型 |
| **交接审批策略** | 见下表（界面文案；口语里有时也称「自主权」） |
| **上班频率** | 心跳 RRULE：10/30 分钟、1/2/3 小时、每天 9:00 等 |
| **上班时间** | 可启用；窗外一般不自动心跳（**现在开始工作**仍可） |
| **工作方式** | **深度工作**（可调工具的 agent loop）/ **轻量工作**（单次 LLM，省成本但能力弱） |

### 交接审批策略三档

| 芯片文案 | 正式交工带下游时 |
|----------|------------------|
| **全自动** | 仅极高风险要「同意派发」；其余自动叫醒下级 |
| **平衡型** | 中风险及以上要「同意派发」（常见默认） |
| **谨慎型** | 几乎都要「同意派发」（推荐上手） |

新开工作项**默认直接开跑**；本表主要管「交工后要不要你点同意派发」。遗留 initiative / 事项路径仍可能按同档风险问你点「同意」。

上手建议：先 **谨慎型** + 较短节奏（如 30 分钟）+ **现在开始工作** 试一轮，确认工具与工作区正常后，再放宽策略或拉长节奏。

### 岗位状态（编制）

| 标签 | 含义 |
|------|------|
| **上班中** | 参与心跳与值班 |
| **已请假** | 暂停自动上班 |
| **草稿** | 未确认上班；可「确认上班」 |
| **已归档** | 不出现在名册、不自动上班；历史保留 |

## 日常操作

| 操作 | 说明 |
|------|------|
| **现在开始工作** | 手动触发一轮值班心跳；可勾选「本轮事项」聚焦某一项 |
| **派发任务** | 填写任务目标 / 补充说明 / 优先级，派给该岗；打开工作轨迹跟进 |
| **小V 委派** | 全局助手左侧选员工，聊天下发临时目标 |
| **请假** / **上班** | 暂停或恢复自动心跳（请假时可能中止本轮） |
| **编辑岗位** | 改职责、节奏、工作区、交接审批策略、工作方式等 |
| **扫码绑定飞书** / **解绑** | 该岗专属飞书机器人（与小V 均可绑） |
| **工作轨迹** | 查看本轮工具与对话（按需打开） |
| **继续本轮** | 在工作项详情上，对未闭环轮次接着干 |
| **归档** | 离开名册；可在「归档」Tab **重新上岗** |
| **删除岗位** | 去掉岗位编制（底层智能体仍在「智能体」页） |

同一员工若已有一轮在跑，再点开工会提示稍候。

### 待审批怎么点

| 按钮 | 何时出现 | 作用 |
|------|----------|------|
| **同意派发** | 芯片「交接审批」：上游已结案、等放行叫醒下游 | **主路径人闸**——同意后系统建子 Task 并 wake 下级 |
| **同意** | 普通/遗留事项审批 | 放行该事项执行（少见；勿与同意派发混淆） |
| **驳回** | 均有 | 须填原因 |
| **关闭无效项** / **丢弃** | 孤儿或无效项 | 清掉卡住的脏数据 |

快捷键（待审批列表）：`Y` 同意 · `N` 驳回 · `J` 下一条。

新开员工任务**默认直接开跑**；你真正频繁点的往往是交工后的 **同意派发**，不是每件事开工前都审。完整「何时审核」见 [概念文](../../explanation/smart-employees.md#干完以后怎么处理什么时候要你审核)。

## 入口、状态与下游（速查）

### 入口（什么会叫醒员工）

| 入口 | 说明 |
|------|------|
| 值班心跳 | 值班台开着 + 上班时间内按节奏 |
| 现在开始工作 | 手动一轮，不受上班时间限制 |
| 派发任务 / 小V | 你点名该岗 |
| 同事跨岗叫醒 | 任意在岗同事（含同级） |
| 正式交工过门 | 上游 handlers + 同意派发（或自动）→ 建子单 wake 直属下级 |
| 子单回执 | soft-wake 上游收束 |

### 状态（员工 Task）

`待开始` → `执行中` →（有下游则）`待闭环` → `已完成`；或 `失败` / `已取消`。

- **待闭环** = 本岗已交、整单未关（常仍算「执行中」分组）。  
- 结案带下游时，系统把完成改写成待闭环，再决定是否挂「同意派发」。

### 下游触发形式

1. **正式交工 handlers** → 仅直属下级 → 可能同意派发 → 系统建子单并叫醒  
2. **同事 wake / 派发** → 任意在岗（含同级）  
3. **你 / 小V 派发** → 任意在岗  
4. **过门后系统 wake**、**子单回执 soft-wake**

### 干完以后

写清任务总结与产出 → 无下游则已完成；有下游则待闭环 → 按策略自动叫醒或等你同意派发 → 下游跑完回执 → 整单已完成。你还可在工作项/任务中心 **确认完成** 或 **打回重做**（验收 ≠ 同意派发）。

图示与细则：[概念文 · 入口 / 状态 / 下游 / 审核](../../explanation/smart-employees.md#入口什么会让员工开始干活)。

## 用小V 委派

全局助手 **小V** 是员工模块的常用入口：临时委派、看进度、绑飞书，不必只在 `#/proactive` 里点菜单。

### 对话：一员工一会话

1. 打开 **小V**
2. 切到 **对话** Tab；左侧联系人列表点选某员工（可悬停展开）
3. 在右侧对该员工直接输入目标并发送
4. 会话内可看进行中任务与最新汇报；历史完成默认折叠，最新在下
5. 需要工具级细节时再点开 **工作轨迹**（默认不打扰主视图）
6. 可用「请求进度」等快捷，或进该员工详情 / 工作日志

也可先对小V 本人聊天（今日汇报、调度建议等），再切到具体员工会话委派。同级之间要对齐时，优先用 **派发任务 / 小V 点名 / 同事跨岗叫醒**，而不是指望正式交工指同级。

### 工作台

**工作台** Tab 汇总今日概览：需要关注、正在执行、刚刚完成、建议推进；常见快捷包括今日汇报、员工进度、待推进、待我审批、问知识库、委派任务。

### 飞书

员工页或小V 内 **扫码绑定飞书** / 解绑；渠道页可查看岗位绑定关系。详见 [飞书集成](../integration/feishu-integration.md)。

## 工作项看板

入口：控制台 **工作项** Tab → `#/proactive/board`。

| 列 | 含义 |
|----|------|
| **待办** | 已建项、尚未执行 |
| **执行中** | 正在干；含本岗已交、整单未关的 **待闭环** |
| **已完成** | 整单闭环 |
| **失败** | 执行失败或本轮汇报未写完等 |

可按员工筛选、**隐藏已完成**。卡片可删除；标「有上游」表示来自下游接力链。待闭环时去待审批看是否卡在「同意派发」，或任务中心看下游进度。

> **验收不在看板列上单独叫「待确认」**  
> 交工后的验收主要在：**工作项详情**（状态如「待你验收 / 交工待验收」）以及 [任务中心](../tasks/task-center.md) 的「待确认」与 **任务总结**。看板用来扫进度与失败项。

### 待审批 vs 交工验收

| | **待审批**（控制台 Tab） | **交工验收**（工作项详情 / 任务中心） |
|--|--------------------------|----------------------------------------|
| 时机 | **交接审批**（同意派发）为主；少数事项「同意」 | **交工后**认不认结果 |
| 动作 | 同意派发 / 同意 / 驳回 | 确认完成 / 打回重做 |
| 超时 | 超时项显示为「审批超时」 | — |

三件事别混：**同意派发** = 放行叫醒下游；**同意** = 放行某事项（少见）；**确认完成** = 验收结果。

## 交工、任务总结与下游接力

### 交工时你会看到什么

员工交工提审后，在 `#/proactive/:code/work/:taskId` 常见：

- 状态：**待你验收** / **交工待验收**
- **完成结果**、**本岗交付物**、**关键发现**、**建议下一步**
- 若有上游：**上游参考产物**
- **查看完整总结** / **任务总结**（做了什么、交付了什么、如何验收）

你在此 **确认完成** 或 **打回重做**；也可用 **工作轨迹**、**继续本轮**，或从 ⋯ 打开 [任务中心](../tasks/task-center.md) 详情。

任务中心「智能体员工」来源 Tab 的列表与详情也会展示任务总结，便于跨岗统一验收。

### 下游接力

交工时可指定 **谁继续处理、读哪些产物**。实现上这是正式 **handlers 交工**：

- **员工只能指定直属下级**（对方「直属上级」必须是自己）；不能把同级填成正式下游，也不能跳级到孙级。  
- 通过后：按交接审批策略可能进「交接审批」→ 你点 **同意派发** → 系统建子 Task 并叫醒下级。  
- **同级要协作**：用「派发任务」、小V 委派或同事 **跨岗叫醒**（任意在岗同事），不要走 handlers。  
- **你**可以在确认页改派同组织任意同事（含同级）。

下游接到后：详情可见上游参考产物与「有上游」；整链在任务中心可按根单看。

测试测出 bug：在「三人同级挂总监」的编制下，优先 **叫醒开发** 修 bug；只有把汇报线配成上下级时，才适合用「同意派发」做测试↔开发正式交工。概念与时序见 [智能体员工是什么](../../explanation/smart-employees.md#两条协作通道先分清)。

## 工作日志与工作汇报

进入 `#/proactive/:code` 可看：

- 岗位信息：交接审批策略、飞书、**值班记忆**、**成本（近 7 日）**、系统前台等
- 值班轮次与工作记录（默认 **近 2 天**；可切今天/昨天/其它日期）
- **本岗全部任务** → 任务中心（智能体员工来源 + 本岗筛选，可搜可分页）
- 「本岗进度」看板按状态扫全貌；过程细节看「工作轨迹」
- 轮次阶段文案：开工记录 → 中途记录 → **本轮小结**（wrap_up）
- 每轮可打开 **工作轨迹**
- 顶栏：**现在开始工作**、编辑岗位、绑飞书、归档等

### 本轮汇报未写完

若出现 **本轮汇报未写完** / **【工作汇报·未完成】**：

1. 打开该轮 **工作过程**，看是否中途中断、超时或未写完工作汇报
2. 可再点 **现在开始工作**（或工作项上 **继续本轮**）；不要只改职责文案碰运气
3. 交付文档是否落盘见下一节
4. 同时看 [健康](#健康与摸鱼) 是否有卡住执行 / 疑似空转

## 交付文档写在哪

方案 / 报告 / 纪要类 Markdown 写到工作空间下：

```text
docs/roles/<agent_code>/<YYYYMMDD-HH>/…
```

- `<agent_code>`：绑定的智能体代码（不是岗位显示名）
- `<YYYYMMDD-HH>`：UTC 小时桶，避免互相覆盖
- 对话里可用 `@@docs/roles/…/某文件.md@@` 引用

约定说明见仓库 `docs/roles/README.md`（产出知识库根）。稳定的操作说明应沉淀进 `docs/user/`，不要把值班产出当产品文档 SSOT。

## 健康与摸鱼

**健康** Tab（及卡片上的「摸鱼中」）帮你判断「在跑但没产出」还是真的在干活：

| 信号 | 建议 |
|------|------|
| **摸鱼中** / 连续空转 | 打开工作轨迹看是否被审批卡住、工具失败、职责太空 |
| **卡住执行** | 执行超过约 45 分钟仍未结束的事项；尝试结束异常轮或再现在开始工作 |
| **今日成本 / 预算告警** | 节奏过密或深度工作过重时收紧节奏 / 改轻量工作 |
| **在岗但待批堆高** | 先去待审批清掉阻塞，再谈职责 |

排查清单也见 [FAQ：员工没产出](../faq.md#问题智能体员工没产出--汇报未写完)。

## 和其它能力怎么选

| 场景 | 更合适 |
|------|--------|
| 跟人多轮聊、临时探索 | 实时聊天 + 切换智能体 |
| 临时把目标派给某岗、看进度汇报 | **小V 委派**（本文） |
| 一次大型多角色软件交付 | [Plan 模式](../chat/plan-mode.md) / [任务中心](../tasks/task-center.md) |
| 到点重复跑固定 prompt | [自动化](../tasks/scheduled-tasks.md) |
| 流程已固定、只换参数再跑 | [应用中心](app-center.md) |
| 长期盯仓库/项目、主动值班与工作汇报 | **智能体员工**（本文） |

值班路径默认不走聊天里的 Supervisor 大图拆派；员工在自己的岗位会话里干活（`proactive:{agent_code}`）。小V 对员工的会话与岗位会话对齐，便于委派与跟进。

## 常见问题

**Q：侧栏没有「智能体员工」？**  
确认客户端版本包含该入口；入口在聊天壳侧栏，文案为「智能体员工」。若提示 Premium / 授权相关，按许可证说明处理。

**Q：雇佣时选不到工作空间？**  
先在聊天侧栏添加本机工作区目录，再回来雇佣。

**Q：心跳在跳但事项全是失败 / 汇报未写完？**  
说明岗在跑、工作汇报没闭环。打开该员工工作轨迹看最后一轮工具与小结；也可在小V 员工会话里按需打开工作轨迹。优先查超时、上班时间窗外、工作区权限、待审批是否堆着，而不是先改职责文案。

**Q：卡片一直显示「摸鱼中」？**  
看健康 Tab 与近几轮工作轨迹：是否无工具调用、是否一直在等审批、职责是否无法落地。试一次「现在开始工作」并收紧职责表述。

**Q：交工后去哪验收？**  
工作项详情的交工待验收，或 [任务中心](../tasks/task-center.md) 打开该任务，先看 **任务总结**，再确认完成或打回。

**Q：交接审批和普通同意有何区别？**  
普通 **同意** 放行本岗事项（少见/遗留）；**同意派发** 放行跨岗下游交接（主路径人闸）。待审批列表里有「交接审批」芯片时用后者。

**Q：同级能互相叫醒吗？正式交工呢？**  
能叫醒（派发任务 / 小V / 同事 wake）。正式交工 handlers **只能直属下级**；同级请用叫醒，或把汇报线改成上下级后再交工。

**Q：和「自动化」有何区别？**  
自动化是按 Cron 跑固定任务提示词；智能体员工是编内岗位：有职责、看板、审批、组织关系与工作汇报。

**Q：改了智能体的 SOUL，员工会变吗？**  
会。岗位绑定的是同一 `agent_code`；人设与工具以「智能体」页为准，岗位页只管职责/节奏/工作区/审批策略。

**Q：归档后历史还在吗？**  
在。归档岗不自动上班、不在名册；可在「归档」Tab 重新上岗。彻底删除岗位不会删除「智能体」页里的 Agent 定义。
