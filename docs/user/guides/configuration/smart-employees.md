# 员工（智能体员工）

> **新手可跳过**：这是进阶功能。日常聊天、先计划 Plan、目标任务都不需要员工；等你需要 AI「按点上班」、定时巡检、跨岗转交审批时，再来本页。

> **先分清智能体和员工**
>
> 1. **区别**：智能体管「会什么」（人设、模型、工具、技能、连接器 MCP）。员工管「何时主动干」（岗位、职责、部门与上级、上班时间、转交审批、工作空间、绑定知识库、预算）。聊天里 @ 智能体不会自动值班。
> 2. **员工能配什么**：加人时填岗位名称、职责、部门、上级、知识库；更多设置里有能力来源、工作空间、工作模型、转交审批（全自动 / 平衡型 / 谨慎型）、自动上班。编辑岗位还可配工作方式、模型思考、系统提示词注入、知识库检索和预算。工具、技能、连接器到「智能体」页改。
> 3. **怎么操作**：侧栏「员工」→「加人」→ 填岗位和至少一条职责 →「确认加人」→ 打开页头「自动上班」，或点「现在开始工作」，急活用小V 派活。交工后到任务中心确认或要求修改。

侧栏入口：**员工**（`#/proactive`）。页头文案是「数字员工 · 员工」。

加人时系统会**自动创建能力**（底层智能体）。只有想沿用已经配好的人设、工具和连接器时，才在「更多设置 → 能力来源」里选未入职的智能体。

逐步上手：[加人：第一个员工](../../tutorials/hire-first-smart-employee.md)。流转概念：[智能体员工是什么](../../explanation/smart-employees.md)。

## 5 分钟上手

1. 侧栏打开 **员工**。
2. 确认页头值班卡是 **自动上班已开启**；否则点 **开启自动上班**。
3. 点 **加人** → 填岗位名称与至少一条职责（可先点模板）→ **确认加人**。
4. 卡片 ⋯ → **现在开始工作**（不必等心跳）。
5. 有转交卡住时：切 **待审批** → **同意派发** 或 **驳回**。
6. 交工验收：进工作项 / [任务中心](../tasks/task-center.md) → **确认完成** 或 **要求修改**。

急活：小V 左侧选该员工，直接下目标。

## 和「智能体」页的关系

| | 智能体（`#/expert`） | 员工（`#/proactive`） |
|--|----------------------|------------------------|
| 回答的问题 | 会什么 | 何时主动干、向谁汇报、干完怎么验收 |
| 你配置的 | 人设、模型、内置工具、技能、连接器、知识库能力 | 岗位名、职责、部门、上级、绑定知识库、工作空间、审批、上班时间表、预算 |
| 怎么用到 | 聊天里 `@`，或作为员工的「能力来源」 | 自动上班、现在开始工作、派发、小V 委派 |
| 不会做的 | 不会自己按点上班 | 不在这里安装 MCP、不在这里改人设正文 |

## 主界面导览

页头值班卡控制**全员**是否按时间表巡检。有待你拍板时，优先清 **待审批**。

| 区域 | 作用 |
|------|------|
| **值班卡** | **开启自动上班** / **关闭自动上班**；显示在岗人数与待批提示 |
| **待审批** | 转交 **同意派发**（主路径）；少数事项 **同意**；孤儿项可关闭 |
| **员工** | 名册卡片：状态、近况、⋯ 菜单 |
| **组织 / 部门** | 部门树与上下级；可调直属上级 |
| **健康** | 今日成本、卡住执行、疑似空转、预算告警 |
| **工作项** | 跳转全员看板 `#/proactive/board` |

飞书 / 企微 / 钉钉：页头可能出现「扫码绑定」提示；也可在卡片或详情里 **扫码绑定 IM**。

### 常用路由

| 路由 | 页面 |
|------|------|
| `#/proactive` | 员工控制台 |
| `#/proactive?tab=approvals` | 直接打开待审批 |
| `#/proactive/board` | 全员工作项看板（可 `?role=<code>&hideDone=1`） |
| `#/proactive/:code` | 该员工详情（上班记录等） |
| `#/proactive/:code/work/:taskId` | 单个工作项详情 |
| `#/proactive/:code/item/:itemId` | 单个事项详情 |

### 员工卡片状态

详情页徽章收敛为三种；名册上一句话会写清草稿 / 请假等：

| 徽章 / 说法 | 含义 |
|-------------|------|
| **工作中** | 本轮正在跑 |
| **在岗** | 参与自动巡检（看 tip 里的下次巡检时间） |
| **已停** | 请假、草稿未确认、或该岗自动巡检被关掉 |
| **草稿** | 未确认上班；⋯ 里点 **确认上班** |
| **请假** | 暂停自动巡检；⋯ 里点 **上班** 恢复 |
| **N 待批** | 该岗有待你处理的审批 |
| **系统前台** | 安装自带岗，偏催办全局待办（勿当普通业务岗乱改删） |
| **疑似空转** | 健康页信号；优先看工作过程 |

点卡片近况进入详情；上班记录默认近 2 天。更早用详情里 **本岗全部任务** 进任务中心。

## 员工能配哪些功能

### 加人时就能填

| 字段 | 说明 |
|------|------|
| **从模板开始** | 研发助理、运维值班、学习助理等预填，仍可改 |
| **岗位名称** | 名册职称 |
| **职责** | 每行一条，写可检查的事。确认加人时至少一条 |
| **部门** / **直属上级** | 编制；正式交工只能派给直属下级 |
| **绑定知识库** | 多选；没有库先去 [知识库](knowledge-base.md) 建 |

### 更多设置（加人）

| 字段 | 说明 |
|------|------|
| **能力来源** | 默认 **自动创建能力**；或 **沿用未入职能力** |
| **管辖工作空间** | 最近目录，或「浏览…」选本机文件夹。空 = 默认工作空间 |
| **工作模型** | 空 = 跟随该能力的默认模型 |
| **转交审批策略** | 全自动 / 平衡型 / 谨慎型（加人默认谨慎型） |
| **自动上班** | 与自动化同一套时间表。**现在开始工作**不受此表限制 |

底部：**保存草稿** / **确认加人**。

### 编辑岗位（五个分区）

| 分区 | 字段 |
|------|------|
| **基本信息** | 绑定智能体、岗位名称、部门、直属上级、职责 |
| **能力与知识** | 工作模型、工作空间、绑定知识库、知识库检索配置、工作方式（深度 / 轻量）、模型思考、系统提示词注入 |
| **工作策略** | 转交审批策略、自动上班时间表 |
| **成本预算** | 每日 / 单次预算（USD，0=不限）、超额策略（跳过上班 / 暂停岗位 / 仅通知） |

工具、技能、连接器数字显示在卡片上，改法仍在「智能体」页。

### 转交审批三档

| 芯片 | 正式交工带下游时 |
|------|------------------|
| **全自动** | 仅极高风险要「同意派发」 |
| **平衡型** | 中风险及以上要「同意派发」 |
| **谨慎型** | 几乎都要「同意派发」（推荐上手） |

新开工作项**默认直接开跑**。本表主要管交工后要不要你放行下游。

### 编制状态

| 状态 | 含义 |
|------|------|
| **在岗 / active** | 可参与心跳 |
| **请假 / paused** | 不自动巡检 |
| **草稿 / draft** | 未确认；需确认上班 |
| **已删除** | 去掉岗位编制；底层智能体仍在「智能体」页 |

名册没有单独的「归档」Tab；不用的岗用请假停巡检，或 **删除岗位**。

## 日常操作

| 操作 | 在哪 | 说明 |
|------|------|------|
| **现在开始工作** | 卡片 ⋯ / 详情 | 立刻跑一轮；不受上班时间限制 |
| **派发任务** | 卡片 ⋯ / 详情 | 写目标后立刻叫醒该岗 |
| **工作过程** | 卡片 ⋯ / 详情 | 看本轮工具与对话 |
| **编辑岗位** | ⋯ | 打开五分区编辑表 |
| **请假** / **上班** / **确认上班** | ⋯ | 停 / 恢复 / 草稿转正 |
| **扫码绑定 IM** | ⋯ / 详情 | 飞书 / 企微 / 钉钉；可多渠 |
| **跟他聊** | 详情顶栏 | 打开该员工主聊天会话 |
| **本岗进度看板** | 详情 ⋯ | 本岗工作项 |
| **本岗全部任务** | 详情 ⋯ | 跳任务中心筛选 |
| **删除岗位** | ⋯ | 移除雇佣，不删底层智能体 |
| **小V 委派** | 小V | 左侧选员工下目标 |

同一岗若已有一轮在跑，再开工会提示稍候。

### 待审批怎么点

| 按钮 | 何时 | 作用 |
|------|------|------|
| **同意派发** | 芯片为交接 / 转交 | 放行叫醒下游（主路径） |
| **同意** | 普通事项审批 | 放行该事项（少见） |
| **驳回** | 均有 | 须填原因 |
| **关闭无效项** / **丢弃** | 孤儿脏数据 | 清掉卡住项 |

快捷键：`Y` 同意 · `N` 驳回 · `J` 下一条。

单岗无下游时待审批经常是空的——正常。细则见 [概念文](../../explanation/smart-employees.md#干完以后怎么处理什么时候要你审核)。

## 员工详情 `#/proactive/:code`

### 顶栏

派发任务 · 跟他聊 · 工作过程 · ⋯（编辑、绑 IM、本岗看板、本岗任务、删除等）

### 分区 Tab

| Tab | 内容 |
|-----|------|
| **上班记录** | 近 2 天 / 今天等轮次日记；本轮小结、工作过程入口 |
| **成长** | 成长与变更记录 |
| **运行数据** | 成本、绩效等运行指标 |
| **配置** | 当前岗位配置摘要（改配置仍用编辑岗位） |

프로필区会展示职责、能力芯片（工具 / MCP / 技能）、工作空间、下次巡检、诊断提示等。

### 本轮汇报未写完

1. 打开该轮 **工作过程**，看是否中断、超时或没写小结。
2. 再点 **现在开始工作**，或工作项上继续本轮。
3. 同时看 **健康** 是否卡住执行 / 疑似空转。不要只改职责文案碰运气。

## 工作项看板 `#/proactive/board`

从控制台 **工作项** Tab 进入。看板列：

| 列 | 含义 |
|----|------|
| **待处理** | 已建、尚未认真开跑 |
| **进行中** | 正在干 |
| **待确认** | 等你验收或拍板 |
| **已完成** | 整单关闭 |

可按岗位筛选、隐藏已完成、切换看板 / 列表。点卡片进工作项或任务详情再决策。

**同意派发**在待审批 Tab / 详情决策区；**确认完成 / 要求修改**在工作项或任务中心详情。别混。

## 交工、下游与验收

### 交工时你会看到

在 `#/proactive/:code/work/:taskId` 或任务中心详情：

- 任务总结（做了什么、交付了什么、如何验收）
- 本岗交付物 / 产物
- 若有下游：转交对象与验收内容 → 可能挂 **同意派发**

你在此 **确认完成** 或 **要求修改**（须写说明）。这和「同意派发」不是一回事。

### 两条下游通道

| 通道 | 谁可以叫谁 | 要不要你审 |
|------|------------|------------|
| **正式交工 handlers** | 员工只能派 **直属下级** | 按转交审批策略，可能要同意派发 |
| **派发 / wake / 小V** | **任意在岗**同事（含同级） | 一般不走交接审批门 |

同级要对齐：用派发或小V，不要指望正式交工指同级。组织树决定正式交工合法目标，不会自动给下级派活。

### 交付文档落盘

方案 / 报告类 Markdown 常写到工作空间下：

```text
docs/roles/<agent_code>/<YYYYMMDD-HH>/…
```

稳定的产品说明应沉淀进 `docs/user/`，不要把值班产出当手册 SSOT。

## 用小V 委派

1. 打开 **小V** → **对话**。
2. 左侧点选某员工，右侧直接下目标。
3. 会话里看进度与汇报；细节再开 **工作过程**。
4. **工作台** Tab 可看今日概览与待我审批等快捷入口。

侧栏「员工」管编制与值班；小V 更适合临时委派与跟进。

## 组织 / 部门

树形看部门与汇报线；可改直属上级、在部门管理里编辑部门。

- 正式交工：**仅直属下级**
- 同级协作：派发 / wake / 小V

## 健康

| 信号 | 建议 |
|------|------|
| 疑似空转 | 打开工作过程：是否无工具调用、是否卡在审批 |
| 卡住执行 | 跑太久未结束；结束异常轮或再「现在开始工作」 |
| 今日成本 / 预算告警 | 放慢节奏，或改轻量工作 |
| 待批堆高 | 先清待审批再谈职责 |

也见 [FAQ：员工没产出](../faq.md#问题智能体员工没产出--汇报未写完)。

## 和其它能力怎么选

| 场景 | 更合适 |
|------|--------|
| 临时问答 | 聊天 `@` 智能体 |
| 临时派给某岗 | **小V** 或「派发任务」 |
| 大型多角色交付 | Plan + [任务中心](../tasks/task-center.md) |
| 到点固定 Prompt | [自动化](../tasks/scheduled-tasks.md) |
| 流程已定只换参 | [工作流（旧名「应用中心」）](app-center.md) |
| 长期盯盘、值班、交工 | **员工**（本文） |

员工值班默认不走聊天 Supervisor 大图拆派；在岗位会话里干活。

## 常见问题

**Q：侧栏找不到入口？**  
文案是 **员工**（`#/proactive`）。若提示授权，按许可证说明处理。

**Q：必须先建智能体吗？**  
不必。加人默认自动创建能力。

**Q：加人时选不到工作空间？**  
用「浏览…」选本机文件夹，或先在聊天里用过某目录（会出现在最近列表）。

**Q：心跳在跳但没产出 / 汇报未写完？**  
打开 **工作过程** 看最后一轮；查超时、待审批是否堆着、工作区权限，再「现在开始工作」。

**Q：交工后去哪验收？**  
工作项详情或 [任务中心](../tasks/task-center.md) → 看任务总结 → 确认完成 / 要求修改。

**Q：同意派发和确认完成有何区别？**  
同意派发 = 放行叫醒下游。确认完成 = 认不认本岗结果。

**Q：同级能互相叫醒吗？**  
能（派发 / 小V / wake）。正式交工只能直属下级。

**Q：和自动化有何区别？**  
自动化是到点跑固定指令。员工是有职责、审批、组织关系与工作汇报的岗位。

**Q：改了智能体的人设，员工会变吗？**  
会。岗位绑的是同一能力；人设与连接器以智能体页为准。

**Q：删除岗位后智能体还在吗？**  
在。「智能体」页里的定义不会一起删掉。
