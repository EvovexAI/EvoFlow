# 员工（智能体员工）

> **新手可跳过**：这是进阶功能。日常聊天、先计划 Plan、目标任务都不需要员工；等你需要 AI「按点上班」、定时巡检、跨岗转交审批时，再来本页。

> **先分清智能体和员工**
>
> 1. **区别**：智能体管「会什么」（名称、系统提示词、人设、工具、技能、连接器 MCP、平台能力）。员工管「何时主动干」（部门与上级、上班时间、交工审核、工作空间、绑定知识库、预算）。名称与提示词与智能体共用，不再单独维护「岗位职责」清单。聊天里 @ 智能体不会自动值班。
> 2. **员工能配什么**：加人时填名称、系统提示词、部门、上级、知识库；更多设置里有能力来源、工作空间、工作模型、交工审核（需要审核 / 无需审核；编辑还可选「有风险才审」）、自动上班。编辑岗位共八段：智能体 · 工作设置 · 内置工具 · MCP · 技能 · 知识库 · 工作策略 · 成本预算——工具与技能可在员工编辑里直接改。
> 3. **怎么操作**：侧栏「员工」→「加人」→ 填名称与系统提示词 →「确认加人」→ 打开页头「自动上班」，或点「现在开始工作」，急活用小V 派活。交工后到任务中心确认或要求修改。

侧栏入口：**员工**（`#/proactive`）。页头文案是「数字员工 · 员工」。

加人时系统会**自动创建能力**（底层智能体）。只有想沿用已经配好的人设、工具和连接器时，才在「更多设置 → 能力来源」里选未入职的智能体。

逐步上手：[加人：第一个员工](../../tutorials/hire-first-smart-employee.md)。流转概念：[智能体员工是什么](../../explanation/smart-employees.md)。

## 5 分钟上手

1. 侧栏打开 **员工**。
2. 确认页头右侧「自动上班」开关是开启状态（状态显示 **已开启**）；否则拨到开。
3. 点 **加人** → 填岗位名称与系统提示词（可先点模板）→ **确认加人**。
4. 卡片 ⋯ → **现在开始工作**（不必等心跳）。
5. 有转交卡住时：切 **待审批** → **同意派发** 或 **驳回**。
6. 交工验收：进工作项 / [任务中心](../tasks/task-center.md) → **确认完成** 或 **要求修改**。

急活：小V 左侧选该员工，直接下目标。

## 和「智能体」页的关系

| | 智能体（`#/expert`） | 员工（`#/proactive`） |
|--|----------------------|------------------------|
| 回答的问题 | 会什么 | 何时主动干、向谁汇报、干完怎么验收 |
| 你配置的 | 人设、模型、工具、技能、连接器、平台能力清单 | 部门、上级、交工审核、上班时间表、预算；编辑里也可改工具 / MCP / 技能 / 知识库 |
| 怎么用到 | 聊天里 `@`，或作为员工的「能力来源」 | 自动上班、现在开始工作、派发、小V 委派 |
| 不会做的 | 不会自己按点上班 | 不在这里安装新的 MCP 服务（装连接器仍去设置 → 连接器） |

员工编辑与智能体编辑改的是同一套能力；在员工 sheet 改工具会立刻作用到该岗。

## 主界面导览

页头开关控制**全员**是否按时间表巡检。有待你拍板时，优先清 **待审批**。

| 区域 | 作用 |
|------|------|
| **自动上班开关** | 页头右侧：状态灯 + **自动上班** + 拨动开关；旁边显示 **已开启 / 已关闭**、在岗人数与待批提示 |
| **待审批** | 转交 **同意派发**（主路径）；少数事项 **同意**；孤儿项可关闭 |
| **员工** | 名册卡片：状态、近况、⋯ 菜单 |
| **组织 / 部门** | 部门树与上下级；可调直属上级 |
| **健康** | 今日成本、卡住执行、疑似空转、预算告警 |
| **工作项** | 跳转全员看板 `#/proactive/board` |

飞书 / 企微 / 钉钉：页头可能出现「扫码绑定」提示；也可在卡片或详情里 **扫码绑定 IM**。

### 常用路由

| 路由 | 页面 |
|------|------|
| `#/proactive` | 员工控制台 |
| `#/proactive?tab=approvals` | 直接打开待审批 |
| `#/proactive/board` | 全员工作项看板（可 `?role=<code>&hideDone=1`） |
| `#/proactive/:code` | 该员工详情（上班记录等） |
| `#/proactive/:code/work/:taskId` | 单个工作项详情 |
| `#/proactive/:code/item/:itemId` | 单个事项详情 |

### 员工卡片状态

详情页徽章收敛为三种；名册上一句话会写清草稿 / 请假等：

| 徽章 / 说法 | 含义 |
|-------------|------|
| **工作中** | 本轮正在跑 |
| **在岗** | 可对话 / 派活；关掉定时巡检或总开关时 tip 可能写「不定时巡检」，**仍算在岗**（只是不自动巡检） |
| **已停** | 请假或草稿未确认（人不可用） |
| **草稿** | 未确认上班；⋯ 里点 **确认上班** |
| **请假** | 整岗暂停；⋯ 里点 **上班** 恢复 |
| **N 待批** | 该岗有待你处理的审批 |
| **系统前台** | 安装自带岗，偏催办全局待办（勿当普通业务岗乱改删） |
| **疑似空转** | 健康页信号；优先看工作过程 |

点卡片近况进入详情；上班记录默认近 2 天。更早用详情里 **本岗全部任务** 进任务中心。

## 员工能配哪些功能

### 加人时就能填

| 字段 | 说明 |
|------|------|
| **从模板开始** | 研发助理、运维值班、学习助理等预填，仍可改 |
| **岗位名称** | 名册职称（与智能体名称共用） |
| **系统提示词** | 写可检查的事。反例：「好好工作」；正例：「每个工作日 09:00 检查 main 分支 CI；红了就写失败报告并 @ 我」。确认加人时不能为空 |
| **部门** / **直属上级** | 编制；正式交工只能派给直属下级 |
| **绑定知识库** | 多选；没有库先去 [知识库](knowledge-base.md) 建 |

### 更多设置（加人）

| 字段 | 说明 |
|------|------|
| **能力来源** | 默认 **自动创建能力**；或 **沿用未入职能力** |
| **管辖工作空间** | 最近目录，或「浏览…」选本机文件夹。空 = 默认工作空间 |
| **工作模型** | 空 = 跟随该能力的默认模型 |
| **交工审核** | 加人两档：**需要审核** / **无需审核**（推荐先选需要审核） |
| **自动上班** | 与自动化同一套时间表。**现在开始工作**不受此表限制 |

底部：**保存草稿** / **确认加人**。

### 编辑岗位（八段导航）

| 分区 | 字段 |
|------|------|
| **智能体** | 绑定智能体、名称、系统提示词、人格 SOUL |
| **工作设置** | 工作模型、工作空间、工作方式、模型思考、系统提示词注入、图片识别、记忆相关等 |
| **内置工具** | 本岗可用的内置工具勾选（可在员工编辑里直接改） |
| **MCP** | 本岗挂载的连接器 / MCP 服务器 |
| **技能** | 本岗技能勾选 |
| **知识库** | 绑定知识库与检索配置 |
| **工作策略** | 交工审核、自动上班时间表、**上班时间窗**、**每轮建单上限**、**风险阈值** |
| **成本预算** | 每日 / 单次预算（USD，0=不限）、超额策略（跳过上班 / 暂停岗位 / 仅通知） |

**平台能力清单**（不设限 / 全量受风险上限 / 全拒 / 自定义域与动作）在智能体编辑的能力面板；影响平台动作闸门与资产目录过滤。员工编辑不单独再开一块，改底层智能体即可。

### 三道自动闸门（P0）

岗位有三道「自动拦住」的门，配置在 **工作策略** 里：

| 闸门 | 配置项 | 作用 |
|------|--------|------|
| **上班时间窗** | 上班时间启用 / 开始小时 / 结束小时 | 定时巡检**只在窗内**开工；窗外到点会被跳过（记为「不在上班时间内」）。人工「现在开始工作」/ 派发**不受**此门限制。跨零点的班次（如 22→6）按夜班处理 |
| **每轮建单上限** | 每轮最多发起事项数（默认 3） | 员工**一轮内**最多新建这么多工作项；超出会被拒绝并提示「已达上限」。防止一轮疯狂造单。设 0 = 本轮不许再开新单 |
| **风险阈值** | 风险阈值 + **是否启用** | 自主档位决定基线；启用后阈值只能**收紧**（不能放宽）。未启用时该字段不生效（保持旧行为） |

### 交工审核三档

后端仍是三档；界面文案：

| 芯片 | 正式交工带下游时 |
|------|------------------|
| **无需审核** | 仅极高风险要「同意派发」 |
| **有风险才审** | 中风险及以上要「同意派发」（编辑可选） |
| **需要审核** | 几乎都要「同意派发」（推荐上手；加人默认） |

新开工作项**默认直接开跑**。本表主要管交工后要不要你放行下游。

### 编制状态

| 状态 | 含义 |
|------|------|
| **在岗 / active** | 可参与心跳；关巡检 / 关总开关仍显示在岗（只停自动巡检） |
| **请假 / paused** | 不自动巡检，人不可用 |
| **草稿 / draft** | 未确认；需确认上班 |
| **已删除** | 去掉岗位编制；底层智能体仍在「智能体」页 |

名册没有单独的「归档」Tab；不用的岗用请假停巡检，或 **删除岗位**。

## 日常操作

| 操作 | 在哪 | 说明 |
|------|------|------|
| **现在开始工作** | 卡片 ⋯ / 详情 | 立刻跑一轮；不受上班时间限制 |
| **派发任务** | 卡片 ⋯ / 详情 | 写目标后立刻叫醒该岗 |
| **工作过程** | 卡片 ⋯ / 详情 | 看本轮工具与对话 |
| **编辑岗位** | ⋯ | 打开八段编辑表 |
| **请假** / **上班** / **确认上班** | ⋯ | 停 / 恢复 / 草稿转正 |
| **扫码绑定 IM** | ⋯ / 详情 | 飞书 / 企微 / 钉钉；可多渠 |
| **跟他聊** | 详情顶栏 | 打开该员工主聊天会话 |
| **本岗进度看板** | 详情 ⋯ | 本岗工作项 |
| **本岗全部任务** | 详情 ⋯ | 跳任务中心筛选 |
| **删除岗位** | ⋯ | 移除雇佣，不删底层智能体 |
| **小V 委派** | 小V | 左侧选员工下目标 |

同一岗若已有一轮在跑，再开工会提示稍候。

### 待审批怎么点

| 按钮 | 何时 | 作用 |
|------|------|------|
| **同意派发** | 芯片为交接 / 转交 | 放行叫醒下游（主路径） |
| **同意** | 普通事项审批 | 放行该事项（少见） |
| **驳回** | 均有 | 须填原因 |
| **关闭无效项** / **丢弃** | 孤儿脏数据 | 清掉卡住项 |

快捷键：`Y` 同意 · `N` 驳回 · `J` 下一条。

单岗无下游时待审批经常是空的——正常。细则见 [概念文](../../explanation/smart-employees.md#干完以后怎么处理什么时候要你审核)。

## 员工详情 `#/proactive/:code`

### 顶栏

派发任务 · 跟他聊 · 工作过程 · ⋯（编辑、绑 IM、本岗看板、本岗任务、删除等）

### 分区 Tab

| Tab | 内容 |
|-----|------|
| **上班记录** | 近 2 天 / 今天等轮次日记；本轮小结、工作过程入口 |
| **成长** | 成长与变更记录 |
| **运行数据** | 成本、绩效等运行指标 |
| **配置** | 当前岗位配置摘要（改配置仍用编辑岗位） |

资料区会展示系统提示词摘要、能力芯片（工具 / MCP / 技能）、工作空间、下次巡检、诊断提示等。

### 本轮汇报未写完

1. 打开该轮 **工作过程**，看是否中断、超时或没写小结。
2. 再点 **现在开始工作**，或工作项上继续本轮。
3. 同时看 **健康** 是否卡住执行 / 疑似空转。不要只改提示词碰运气。

## 工作项看板 `#/proactive/board`

从控制台 **工作项** Tab 进入。看板列：

| 列 | 含义 |
|----|------|
| **待处理** | 已建、尚未认真开跑 |
| **进行中** | 正在干 |
| **待确认** | 等你验收或拍板 |
| **已完成** | 整单关闭 |

可按岗位筛选、隐藏已完成、切换看板 / 列表。点卡片进工作项或任务详情再决策。

**同意派发**在待审批 Tab / 详情决策区；**确认完成 / 要求修改**在工作项或任务中心详情。别混。

## 交工、下游与验收

### 交工时你会看到

在 `#/proactive/:code/work/:taskId` 或任务中心详情：

- 任务总结（做了什么、交付了什么、如何验收）
- 本岗交付物 / 产物
- 若有下游：转交对象与验收内容 → 可能挂 **同意派发**

你在此 **确认完成** 或 **要求修改**（须写说明）。这和「同意派发」不是一回事。

### 两条下游通道

| 通道 | 谁可以叫谁 | 要不要你审 |
|------|------------|------------|
| **正式交工 handlers** | 员工可派 **直属下级** 或 **同一上级下的平级** | 按交工审核，可能要同意派发 |
| **派发 / wake / 小V** | **任意在岗**同事（含同级） | 一般不走交接审批门 |

同级要对齐：用派发或小V；同一 `reports_to` 上级下的平级也可以直接正式交工。组织树决定正式交工合法目标，不会自动给下级派活。

### 交付文档落盘

方案 / 报告类 Markdown 常写到工作空间下：

```text
docs/roles/<agent_code>/<YYYYMMDD-HH>/…
```

稳定的产品说明应沉淀进 `docs/user/`，不要把值班产出当手册 SSOT。

## 用小V 委派

1. 打开 **小V** → **对话**。
2. 左侧点选某员工，右侧直接下目标。
3. 会话里看进度与汇报；细节再开 **工作过程**。
4. **工作台** Tab 可看今日概览与待我审批等快捷入口。

侧栏「员工」管编制与值班；小V 更适合临时委派与跟进。

部门群聊里，派工气泡会显示 **排队中 / 回答中 / 已回 / 失败**，便于旁观谁在办。

## 健康

| 信号 | 建议 |
|------|------|
| 疑似空转 | 打开工作过程：是否无工具调用、是否卡在审批 |
| 卡住执行 | 跑太久未结束；结束异常轮或再「现在开始工作」 |
| 今日成本 / 预算告警 | 放慢节奏，或改轻量工作 |
| 待批堆高 | 先清待审批再谈提示词 |

也见 [FAQ：员工没产出](../faq.md#问题智能体员工没产出--汇报未写完)。

| 场景 | 更合适 |

## 常见问题

**Q：侧栏找不到入口？**  
文案是 **员工**（`#/proactive`）。若提示授权，按许可证说明处理。

**Q：必须先建智能体吗？**  
不必。加人默认自动创建能力。

**Q：加人时选不到工作空间？**  
用「浏览…」选本机文件夹，或先在聊天里用过某目录（会出现在最近列表）。

**Q：心跳在跳但没产出 / 汇报未写完？**  
打开 **工作过程** 看最后一轮；查超时、待审批是否堆着、工作区权限，再「现在开始工作」。

**Q：交工后去哪验收？**  
工作项详情或 [任务中心](../tasks/task-center.md) → 看任务总结 → 确认完成 / 要求修改。

**Q：同意派发和确认完成有何区别？**  
同意派发 = 放行叫醒下游。确认完成 = 认不认本岗结果。

**Q：同级能互相叫醒吗？**  
能（派发 / 小V / wake）。正式交工也可派给**同一上级下的平级**；跨上级不行。

**Q：和自动化有何区别？**  
自动化是到点跑固定指令。员工是有提示词、审批、组织关系与工作汇报的岗位。

**Q：关了自动上班，员工是不是「已停」？**  
不是。关总开关或关该岗巡检仍显示 **在岗**（可对话、可派活），只是不定时巡检；**已停**只用于请假和草稿。

**Q：改了智能体的人设，员工会变吗？**  
会。岗位绑的是同一能力。

**Q：删除岗位后智能体还在吗？**  
在。「智能体」页里的定义不会一起删掉。
