# 工作流

> **新手可跳过**：这是进阶功能，日常聊天和先计划 Plan 模式就够用。等你需要把同一套步骤反复跑、每次只换参数（比如每周换个周次生成周报）时，再来本页。

侧栏入口：**工作流**（`#/apps`）。页头文案是「工作流」——把跑通的流程存成模板，以后填参数就能直接跑，不用每次从头聊。

旧文档里的「应用中心」指的就是这一页。任务中心来源筛选里对应标签也是 **工作流**（含自动化触发的跑次）。

> 别和任务详情里的执行流程图搞混：`#/apps` 是**搭流程的画布**，要你事先编排；任务详情里的 `#/workflow/:id` 是**某次运行的执行步骤图**，不用事先来这里建任何东西。

推荐路径：新建 → 画布编排 → **调试** 试跑 → **发布** → 卡片 **▶ 运行** 或 ⋯ **填参运行** → 在 [任务中心](../tasks/task-center.md) 看执行。

---

## 5 分钟固化第一条

1. 侧栏打开 **工作流**，点 **新建工作流 ▾** → **空白工作流**（或从模板 / 从任务沉淀）。
2. 进画布：用 **节点** 加步骤，给每步选智能体、写清指令；用线定先后。
3. 点 **参数**，填 **工作流目标**，并声明运行参数（可为空）。
4. 点 **调试** 在画布内填参试跑（草稿也可）。
5. 满意后点 **发布**。回到列表，已发布卡片点 **▶ 运行** 填参开跑。

## 和聊天 / 任务 / 员工的区别

| 能力 | 适合 |
|------|------|
| **实时聊天 / Plan** | 探索、一次性复杂协作 |
| **任务中心** | 看某次执行、验收、同意派发；来源可筛「工作流」 |
| **员工** | 岗位值班、心跳巡检、跨岗转交 |
| **自动化** | 到点触发提示词或已发布工作流 |
| **工作流**（本文） | 流程已固定，只换参数反复开跑 |

注意：`#/workflow/:id` 是协作任务的全屏 DAG（从任务详情打开），**不是**本页画布。画布在 `#/apps/:id`。

| 路由 | 用途 |
|------|------|
| `#/apps` | 工作流列表 |

## 列表页

页头提示：① 点卡片进画布编排 → ② **发布** → ③ ⋯ **填参运行**（已发布卡片上也有 **▶ 运行**）。

| 控件 | 说明 |
|------|------|
| 筛选 | **活跃** / **已归档** / **全部** |
| 搜索 | 「搜索工作流…」按名称、描述 |
| **新建工作流 ▾** | **空白工作流** / **从模板创建** / **从任务沉淀** |
| **刷新** | 重载列表 |
| 卡片 | 点空白处进画布；显示步数、参数数、状态徽章 |
| 状态 | **草稿** / **已发布** / **已归档** |

### 已发布卡片

| 操作 | 说明 |
|------|------|
| **▶ 运行** | 进 `#/apps/:id/run` |
| **编辑流程** | 回画布 |
| ⋯ **填参运行** | 同运行 |
| ⋯ **编辑信息** | 改名称、描述、图标、执行方式 |
| ⋯ **归档** | 离开活跃列表；不能新开填参 / API；可 **恢复为草稿** |
| ⋯ **删除** | 定义与运行记录一并删除 |

草稿卡片没有底部运行按钮；点卡片进画布调试，满意再发布。空态可 **创建空白工作流** 或 **从模板创建**。

## 画布 `#/apps/:id`

工具栏（与界面一致）：

| 控件 | 说明 |
|------|------|
| 返回 | 回工作流列表 |
| 名称 | 可直接改；未命名占位「未命名工作流」 |
| 状态徽章 | 草稿 / 已发布 / 已归档 |
| **节点** | 打开 / 收起节点库 |
| **参数** | 打开「工作流设置」（目标、执行方式、运行参数） |
| **历史** | 跳转运行历史 |
| **版本** | 版本快照：查看 / 恢复为草稿 |
| **API** | Key 与调用示例（须已发布） |
| **调试器** | 单步 / Trace 类调试入口 |
| **整理** | 自适应画布视图 |
| **保存** | 存草稿；已发布上保存不会降级为草稿 |
| **发布** | 列表填参运行与 API 的前置条件 |
| **调试** | 画布内填参试跑（草稿也可） |

节点库含系统节点（如开始、输出）与智能体步骤。点节点在右侧配置：选智能体、写步骤说明。开始节点旁可写 **工作流目标**。

### 工作流设置（点「参数」）

标题是「工作流设置」：

| 区块 | 内容 |
|------|------|
| **工作流目标** | 必填，一句话说明要完成什么 |
| **详细描述** | 可选；可「根据工作流目标自动生成」 |
| **执行方式** | **按步骤自动跑完**（推荐）或 **先确认计划再执行**（高风险，生成计划后需人工确认） |
| **调度触发时自动执行** | 定时或接口触发时无需人工确认 |
| **运行参数** | 填参页 / OpenAPI 用的字段表 |

保存设置点 **保存设置**。

发布成功后可引导 **填参运行** 或 **创建 API Key**。

## 填参运行 `#/apps/:id/run`

| 控件 | 说明 |
|------|------|
| ← 工作流列表 | 返回 |
| **编辑流程** | 回画布 |
| 参数表单 | 按定义填写 |
| **运行** | 启动；跑次进任务中心，来源为「工作流」 |
| 运行中 | 可 **暂停** / **继续** / **取消**（以界面按钮为准） |

页上说明：填参 → 运行 → 看结果；改流程去「编辑流程」。发布后可在画布 **API** 建 Key。

监督模式（先确认计划）启动后，需在任务里确认再执行。

---

## 运行历史 `#/apps/:id/history`

- 分页浏览历次运行
- 点 **查看结果** 打开大屏详情（节点产出、最终 HTML 等）
- **← 返回画布** 回编辑器

调试坞内也可 **使用相同参数再次运行**、**查看全部产出**、**查看任务详情**。

## 常见问题

**点运行没反应？**  
确认状态是 **已发布**。草稿用画布 **调试**，不要指望列表 ▶ 运行。

**画布调试成功，列表却跑不了？**  
调试可在草稿上试；列表运行要求已发布。

**API 灰掉 / 建不了 Key？**  
先 **发布**，再开画布 **API**。

**和自动化怎么配合？**  
先发布工作流，再到自动化里选它并设日程。需要无人确认时勾选「调度触发时自动执行」。

**`#/workflow/:id` 是不是画布？**  
不是。那是协作任务的全屏工作流视图；编排模板在 `#/apps/:id`。
