# 案例一：雇佣运维员工——运维值班

> **场景：你维护 3 台服务器（gateway、langgraph、postgres），每天都要检查是否健康，有异常要告警。**
>
> 以前：每天 SSH 登录、敲命令、人工看日志……重复劳动。
>
> 用智能体员工：雇一个「运维值班」员工，定时上班检查、异常告警、下班工作汇报；有事项或交接时在待审批处理，交工后在工作项/任务中心看任务总结验收。

## 操作步骤

### 1. 创建运维角色

在「智能体」页创建角色，人设示例：

```
你是一个专业的运维工程师，擅长检查服务器健康状态、分析日志、排查故障。
检查时先确认服务可达性，再检查关键指标，最后汇总报告。
异常时先分析根因再建议修复方案，不轻易下结论。
```

配好 `terminal` 工具（用于 curl / ping 检查）和飞书推送权限。

### 2. 雇佣为员工

进入「智能体员工」页，点「雇佣员工」：

| 字段 | 填写示例 |
|------|----------|
| **绑定智能体** | 选上一步创建的运维角色 |
| **岗位名称** | 运维值班 |
| **职责** | 每 30 分钟检查 gateway / langgraph / postgres 健康状态；异常时分析根因并推送飞书告警；下班前写值班报告 |
| **管辖工作空间** | 选一个目录，用于存放值班报告 |
| **交接审批策略** | **谨慎型**（带下游交工几乎都要「同意派发」，推荐上手） |
| **上班频率** | 每 30 分钟 |
| **上班时间** | 09:00–20:00 |

### 3. 开值班

值班台点「开启自动上班」，员工开始上岗。

### 4. 日常处理

- **09:00**：员工自动上班，开始检查服务
- **09:30**：第一轮完成，值班报告写到工作空间 `docs/roles/<code>/<日期>/` 下
- **遇到异常**：若走事项审批，待审批出现后点 **同意** 再推告警；新开任务本身默认会直接跑
- **交工带下游时**：待审批常见「交接审批」→ 用 **同意派发**（不是普通同意）
- **20:00**：写工作汇报，下班
- **验收**：工作项详情或任务中心看 **任务总结**，确认完成 / 打回

日常扫一眼待审批；有交工再去任务中心验收。单岗多数时候没有「同意派发」。

## 核心要点

| 概念 | 说明 |
|------|------|
| **岗位 ≠ 角色** | 角色是"会什么"，岗位是"什么时候主动干、干到哪" |
| **交接审批策略三档** | 主要管交工后要不要「同意派发」：谨慎 / 平衡 / 全自动 |
| **同意派发 ≠ 确认完成** | 前者放行叫醒下游；后者是验收结果 |
| **工作汇报** | 写在工作空间 `docs/roles/<agent_code>/<YYYYMMDD-HH>/` 下 |
| **现在开始工作** | 不受上班时间限制，随时手动触发一轮值班 |
