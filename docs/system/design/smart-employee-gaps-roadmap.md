# 智能体员工体系：缺口与补齐方案

> **用途**：盘点当前「智能体员工」相对完整叙事还缺什么，以及**具体怎么补**（产品 / 工程 / 运营）。  
> **不是**用户操作手册；机制说明见 [智能体员工是什么](../../user/explanation/smart-employees.md)，组织画像见 [谁在用、怎么协作](../../user/cases/smart-employee-playbooks.md)。  
> **已具备（基线）**：自动上班、派发/小V/同级叫醒、正式交工仅直属下级、同意派发与待闭环、任务中心切片、员工日记默认近 2 天、健康/没干活/卡住执行等提示。

**阅读方式**：先看「优先级总表」，再按章节落地；每项都含 **缺口 → 目标 → 方案 → 验收**。

## 优先级总表

| 优先级 | 主题 | 为何先做 | 建议窗口 |
|--------|------|----------|----------|
| P0 | 开箱成功：安装 + 模型 + 雇成第一岗 | 抖音/飞书来的人死在这里最多 | **进行中**：飞书文稿已备；无模型拦截确认上班；雇佣模板 5 个 |
| P0 | 失败说人话：汇报未写完 / 没干活 / 待审批卡住 | 口碑与私信成本 | **已做**：名册/健康/员工页诊断芯片 + 一键动作 |
| P1 | 岗位模板（画像 → 一键雇佣） | 文档 18 类画像无法变成产品 | **已做首批 5 个**（研发助理/运维值班/学习助理/内容策划/文档管理员） |
| P1 | 本岗列表/分页与任务中心彻底打通 | 数据变多后日记不够 | **部分完成**：近 2 天日记 + 员工页「日记\|列表」+ 深链；看板默认近 7 天 |
| P1 | 国内获客漏斗（飞书落地页 + 网盘） | 个人开发者无公司也能跑 | **文稿已备** → [feishu-landing](../../user/meta/feishu-landing-smart-employees.md)；网盘链路由你粘贴 |
| P2 | 成本熔断显眼化、通知汇总 | 烧钱与漏批 | 模板之后 |
| P2 | 效果周报（省了什么） | 续用与内容素材 | 有真用户后 |
| P3 | 多账号企业协作 / 强隔离 | 叙事上限，非当前主路径 | 有收入后再做 |

## 1. 产品体验缺口

### 1.1 本岗历史：日记够近、列表不够

**缺口**  
员工页默认近 2 天日记 +「本岗全部任务」跳任务中心；列表视图已起步，但翻页/搜索仍依赖任务中心；工作板接口仍有条数上限，看板无服务端分页。

**目标**  
近况看日记；翻历史像任务中心一样稳（筛 / 搜 / 分页），不必记住两个心智模型。

**方案**

1. **短期（已部分完成）**  
   - 日记默认「近 2 天」；导航「本岗全部任务」→ `#/tasks?source=role&agent=role:岗位名`。  
   - 保持交叉链接：工作项详情 ↔ 任务中心详情。
2. **中期（已部分落地）**  
   - 员工页视图切换：**日记 | 列表**（列表按状态筛最近工作板条目；翻页仍走任务中心）。  
   - 列表后续可复用任务中心行组件 / 服务端分页。  
   - `proactiveRoleWorkBoard` 支持 `cursor` / `offset` + `limit`，或列表路径直接走 `listAllTasks` 客户端按岗过滤并分页（数据量中等时可接受）。
3. **看板**  
   - 「隐藏已完成」保留；增加「仅近 7 天」默认，避免全量卡顿。

**验收**

- [x] 单岗 200+ 历史 Task 时，日记仍只渲染近 2 天且不卡（依赖工作板 limit，日记再按日裁剪）。  
- [x] 「本岗全部任务」打开后来源 Tab=智能体员工、岗位下拉已选中。  
- [x] （中期起步）员工页「列表」可按状态筛选；翻页仍走任务中心。

### 1.2 失败可解释性弱

**缺口**  
「本轮汇报未写完」「近期没干活」「卡住执行」、待审批堆积，用户仍需自己翻工作过程；缺**一句话原因 + 下一步按钮**。

**目标**  
健康条 / 卡片上直接给出可点动作，而不是只报警。

**方案**

| 症状 | 诊断逻辑（示意） | 一键动作 |
|------|------------------|----------|
| 汇报未写完 | 末轮无 wrap_up / 工具超时 / 窗外未自动上班 | 「打开本轮过程」「现在开始工作续跑」「检查上班时间」 |
| 近期没干活 | 连续 N 轮无工具或空转比高 | 「收紧职责示例」「现在开始工作试一轮」「看过程」 |
| 卡住执行 | executing > 阈值（约 45 分钟） | 「标记失败/取消」「打开过程」「请假」 |
| 待审批堆高 | pending 交接审批或事项 | 「去待审批」「筛选本岗同意派发」 |
| handlers 校验失败 | 交工指了同级/越级 | 文案：**改用叫醒** / **改直属上级** / **你去改派」 |

实现落点：

- 前端：员工卡片近况、健康 Tab、员工页诊断条，统一 `proactive-role-diagnosis.js`。  
- 后端：可复用/扩展 proactive health 接口，返回 `code + message + actions[]`（当前前端聚合即可）。  
- 文档：FAQ 与仓库内 `.cursor/skills/proactive-duty-debug/` 排障技能对齐同一套原因码。

**验收**

- [x] 名册 / 健康 / 员工页可出现诊断码与可点动作（待批、没干活、卡住、汇报未写完、未绑工作区）。  
- [x] 「去待审批」可从诊断条直达待审批 Tab。

### 1.3 交工 / 叫醒易用错

**缺口**  
规则已实现（handlers 仅直属下级；wake 可同级），但 UI 仍可能让用户/模型填错下游。

**目标**  
填 handlers 时**选不到非法对象**；同级协作引导去「派发/叫醒」。

**方案**

1. ~~交工确认页：下游下拉**只列出直属下级**；空列表时提示「先配组织树，或改用派发/叫醒」。~~ **已做**（`task-handlers.js` + 用户改派开关）。  
2. 非法提交时后端错误映射为中文固定文案（已有则统一到面板 toast）。  
3. 小V / 职责提示词：注入「同级用 wake，勿填 handlers」。  
4. 用户改派：保持可改派同级（与现规则一致），UI 标注「用户改派可突破」。

**验收**

- [x] 交工编辑默认仅直属下级；勾选「用户改派」可扩名册。  
- [ ] 三人同级挂总监时，测试岗交工下拉看不到前端岗（手工回归）。  
- [ ] 同级叫醒入口在派发/小V 仍可用。

---

### 1.4 三闸易混（同意派发 / 同意 / 确认完成）

**缺口**  
文档已对齐，产品默认路径仍可能让「单岗值班」用户看到过多审批概念。

**目标**  
单岗无下游：几乎只碰验收；有下游才出现同意派发。

**方案**

1. 雇佣向导：选「单岗值班」模板 → 默认不强调交接审批；策略仍可选谨慎型但文案写清「有下游才问你」。  
2. 待审批空态文案：「新任务默认会跑；这里常见是交工后的同意派发」。  
3. 工作项详情：三按钮分区标题固定（交接 / 事项 / 验收）。

**验收**

- [ ] 新用户按教程雇单岗（如研发助理），全程可不出现「同意派发」仍能收交班。  
- [ ] 有下游时，待审批芯片「交接审批」与同意派发按钮绑定清晰。

---

### 1.5 通知与汇总不足

**缺口**  
飞书可绑，但「待审批超时 / 待闭环堆积 / 卡住执行」缺少稳定汇总触达。

**目标**  
每天一次摘要推到飞书或面板铃铛，避免漏批。

**方案**

1. 定时任务（或值班引擎附带）：每日固定时刻汇总 `pending_approval`、`awaiting_close`、卡住执行数。  
2. 有绑定飞书则推卡片；无则面板「今日待办」红点。  
3. 谨慎型用户默认开；全自动可关。

**验收**

- [ ] 故意留 1 条同意派发过夜，次日摘要能提到。

## 2. 体系能力缺口

### 2.1 行业画像未产品化（岗位模板）

**缺口**  
[组织与协作玩法](../../user/cases/smart-employee-playbooks.md) 有 18 类组织树与职责例子，雇佣时仍靠手写。

**目标**  
「选画像 → 预填职责/节奏/策略/建议组织」一键上岗。

**方案**

1. 模板清单：`evopanel/src/lib/proactive-hire-templates.js`（职责 / 节奏 / 策略预填）。  
2. 雇佣弹窗：「从模板开始」→ 仍可改职责。  
3. **已上线 5 个**：研发助理、运维值班、学习助理、内容策划、文档管理员。  
4. 后续补：教研助理、会务助理等；与 playbooks 锚点互链，避免两套文案漂移。

**验收**

- [x] 雇佣弹窗可选模板预填职责后确认上岗（无需从空白手打）。  
- [ ] 从模板雇佣后「立即开工」并落盘一份报告/清单（依赖真机回归）。  
- [ ] 模板红线出现在职责原文中（可被用户看见）。

---

### 2.2 工作区隔离偏软

**缺口**  
多客户靠「一岗一盘」自觉；缺硬隔离与敏感操作默认禁。

**目标**  
外包/多客户画像下，串盘难度显著上升。

**方案**

1. 雇佣时强制选管辖工作空间；系统前台除外。  
2. 模板级 `denied_tools` 提示（财务/医护模板默认不给写生产库/不给终端高危）。  
3. （中期）任务执行上下文校验：工具路径必须落在管辖目录。  
4. 文档继续强调一客户一盘（playbooks §6）。

**验收**

- [ ] 未绑工作区无法确认上岗（或强警告不可跳过）。  
- [ ] 财务模板默认工具集不含危险写权限（可手动加，需二次确认）。

---

### 2.3 缺少「效果周报」

**缺口**  
用户难回答「这岗有没有用」；也缺抖音素材。

**目标**  
每岗每周一页：轮次、交付物数、待你处理次数、失败原因 Top。

**方案**

1. 复用 cost/performance 接口，加 `weekly_digest`（或前端聚合近 7 日 Task）。  
2. 员工页「履职周报」折叠区展示；支持「复制为分享文案」。  
3. 可选推飞书。

**验收**

- [ ] 活跃岗能生成至少含「上岗次数 / 完成数 / 待审批数」的周报。

---

### 2.4 企业多账号协作（刻意后置）

**缺口**  
当前是本机组织树 + 单用户人闸，不是多人审批 OS。

**目标**  
在有付费与主体之前，**不承诺**多租户编制；文档与宣传避免「替代整家公司 HR」。

**方案**

1. 对外文案：个人/小团队本机数字员工。  
2. 路线图记为 P3：账号、角色权限、审计日志、云端同步。  
3. 现有「老板 + 技术搭档」画像用「同一台机器两个习惯」满足，不强行上云。

**验收**

- [ ] 获客文案与能力边界一致（抽查飞书落地页 / 抖音口播）。

---

## 3. 可靠与运维缺口

### 3.1 值班稳定性

**缺口**  
空转、卡 executing、交班失败仍是高频差评。

**方案**

1. 入口恢复：新一轮开工前关闭上一轮僵尸 check_in（设计稿已有思路则落地为默认）。  
2. 卡住执行：健康页一键批量「标记失败并释放」。  
3. 交班：wrap_up 失败重试 1 次 + 失败原因写入本轮小结。  
4. 与 §1.2 诊断码共用。

**验收**

- [ ] 连续 24h 值班，executing 堆积可被健康页一键清到可解释状态。  
- [ ] 交班失败率在试用日志中可统计下降（自建简单计数即可）。

---

### 3.2 成本可见与熔断

**缺口**  
岗级成本有展示，但对新用户不够「怕」；易在抖音演示时烧模型费。

**方案**

1. 雇佣时展示「预估每轮费用」说明（粗估即可）。  
2. 日预算阈值：超限暂停该岗心跳并通知。  
3. 演示模板默认更长节奏（如 2h）降低误触。

**验收**

- [ ] 超预算后该岗不再自动心跳，面板有明确恢复入口。

---

### 3.3 安装与模型（开箱第一关）

**缺口**  
智能体员工价值在「雇岗」之后；之前死于安装/模型。

**方案**

1. **飞书落地页**固定结构：下载（网盘）→ 装好 → 配模型（截图）→ 雇模板岗 → 立即开工。  
2. 产品内：无模型时阻断雇佣并深链设置页。  
3. GitHub 仅作开发者旁路，写在飞书文末。

**验收**

- [ ] 按飞书文档，非开发者可在 15 分钟内看到第一次交班/清单（自测 3 人）。

---

## 4. 商业化与获客缺口（个人开发者）

### 4.1 传播证据不足

**缺口**  
体系完整 ≠ 15 秒可懂。

**方案**

1. 只打一个切口（建议：独立开发者 · 研发助理模板）。  
2. 固定演示脚本：雇佣模板 → 立即开工 → 交班/清单出现。  
3. 录 10 条同素材不同钩子；评论置顶飞书链接。

**验收**

- [ ] 有可复用的竖屏演示素材与口播稿（不必追播放量数字）。

---

### 4.2 转化漏斗未建

**缺口**  
下载在 GitHub，抖音人群转化差。

**方案**

1. 飞书文档主入口 + 网盘安装包。  
2. 反馈：微信号或飞书群（一个即可）。  
3. 成功标准：10 个真实「雇成岗并跑通一轮」反馈，再谈收费与办主体。

**验收**

- [ ] 抖音主页链到飞书而非 GitHub。  
- [ ] 私信/群里能复述至少 3 个真实卡点并回写到 §1 诊断。

---

### 4.3 资质与主体

**缺口**  
无公司、无资质；不影响先获客，影响收款与企业认证。

**方案**

1. 现阶段：个人号内容 + 免费/赞赏/不急着对公。  
2. 有稳定需求后：个体户或小微、支付、软著可选。  
3. 不在产品内承诺「企业级合规」直到有主体与审计能力。

**验收**

- [ ] 飞书页「关于作者」诚实写明个人开发者与能力边界。

## 5. 建议实施顺序（可执行甘特）

```text
第 1～2 周（P0）
  ├─ 飞书落地页 + 网盘包 + 口播演示（研发助理）
  ├─ 失败诊断芯片（交班/摸鱼/卡住/待审批）
  └─ 无模型阻断雇佣

第 3～4 周（P1）
  ├─ 首批 5 个岗位模板（与 playbooks 对齐）
  ├─ 员工页「列表」或强化任务中心深链体验
  └─ handlers 下拉仅直属下级

第 5～6 周（P2）
  ├─ 日预算熔断 + 每日待办摘要（飞书/铃铛）
  └─ 履职周报一键复制

以后（P3）
  └─ 多账号 / 强隔离 / 云端编制（有收入再开）
```
