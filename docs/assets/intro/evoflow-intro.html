为什么是 EvoFlow Why EvoFlow

多数 AI 工具擅长聊几句或写一段代码。EvoFlow 要解决的是——把一件多步的事做完，并且可规划、可审批、可观测、可沉淀、可再跑。

Most AI tools are great at chatting or writing a snippet. EvoFlow tackles a different problem — finish a multi-step task with planning, approval, observability, compounding memory, and re-runnability.

CHAT × PLAN × GOAL

对话壳分四档行为

Four-mode chat shell

Ask 快速问答、Agent 新建、Plan 先对齐再开工、Goal 长任务后台自驱——一行话切档，控制 AI 干多少。

Ask for Q&A, Agent for action, Plan to align first, Goal for long-running background work — one line switches AI behavior.

SUPERVISOR

超级总控拆任务

Supervisor decomposes

澄清意图 → 出方案 → 拆成 DAG 子任务 → 按能力画像分发到子 Agent；异常局部重编排，进度全局可观测。

Clarify → plan → split into a DAG of subtasks → dispatch by capability profile; locally re-plan on failure, observable end-to-end.

SANDBOX

沙箱里真执行

Real work in sandboxes

本地 / Docker / 可选 K8s 三种隔离执行面，文件操作、命令、命令链可放心交给 Agent；默认权限 + 审计。

Local / Docker / optional K8s isolation — files and shell commands run for real with default permissions and audit logs.

核心能力 Capabilities

八块能力，按控制平面入口展开

Eight building blocks, organized by control-plane entry

它们是 EvoFlow 的一等公民——不是边角配置。下面是按「你点哪里、得到什么」组织的能力地图。

These are first-class citizens — not buried config. Below is the capability map organized by what you click and what you get.

01 · DO THE WORK

把事做完：Plan · Goal · Teams · 任务中心

Finish the work: Plan · Goal · Teams · Task Center

Plan 先澄清、出可修订计划再动手；Goal 让长任务后台自驱；Agent Teams / 项目团队多 Agent 隔离上下文、委派与重试；任务中心看板 + 验收——执行层可见、可打回。

Plan first, revise, then execute. Goal runs long tasks in the background. Agent Teams isolate context per agent. Task Center shows boards and review.

02 · PRODUCTIZE FLOWS

固定业务：应用中心 · 自动化

Productize recurring work: App Center · Automation

应用中心画布编排多节点工作流 → 发布 → 填参再跑；自动化按 Cron 或一次性触发固定 Prompt，可推 IM。一次配好，长期生效。

Compose multi-node flows in the canvas → publish → run with parameters. Schedule with cron or one-shot and push to IM. Set once, run many.

03 · ORG SHAPE

组织形态：智能体 · 智能体员工 · 小V

Org shape: Agents · Employees · XiaoV

智能体定义「会什么」（人设 / 工具 / 技能 / MCP）；智能体员工定义「何时干、谁放行」（值班 / 职责 / 关键审批 / 汇报）；小V 前台临时委派，不必改岗位合同。

Agents define 'what they can do'. Smart employees define 'when they work and who approves'. XiaoV handles ad-hoc dispatch without role edits.

04 · WORKSPACE

工程上下文：工作空间 · 代码索引

Engineering context: Workspace · Code index

工作空间绑定本地项目目录、侧栏分组、读写边界；代码索引产出导入 / 引用 / 类型图谱，Agent 用 search_code_index 检索——不只是全文搜。

Workspaces bind local projects with read/write boundaries. The code index exposes import / reference / type graphs; agents query via search_code_index.

05 · SELF-EVOLUTION

自我进化：资产中心

Self-evolution: Asset Center

画像 / 记忆跨会话记得偏好与约定；经验沉淀把「怎么做」固化下来；反思过程形成可回顾的进化轨迹。对话里直接说「记住 / 沉淀 / 反思」就能存。

Profile / memory carry preferences across sessions. Experience capture freezes 'how to do this'. Reflection journals form an evolvable trail. Say 'remember / capture / reflect' in chat to persist.

06 · GOVERNANCE

治理套件：多账号 · 费用 · 观测 · 安全

Governance: Accounts · Cost · Observability · Security

多账号 / ACL / 企业 SSO；Token 与费用账本按日 / 模型拆分；运维观测覆盖会话 / 工具 / 模型 / Gateway 热点；安全中心管沙箱、默认权限、终端策略、审计。

Multi-account with ACL and SSO. Token / cost ledger per day and model. Observability covers sessions, tools, models, gateway. Security Center handles sandbox defaults and audit.

07 · EXTENSIBILITY

扩展与触达：资源市场 · 技能 · MCP · IM · 多模型

Extensions & reach: Marketplace · Skills · MCP · IM · Multi-model

资源中心与资源市场安装资源包与Agent应用；SKILL.md 技能包 + MCP（stdio / SSE / HTTP）连接任意外部服务；飞书 / 微信 / Slack / Telegram 等 IM 与桌面同线程心智；设置里配服务商与主模型，开箱改。

Install resource packs from the marketplace. SKILL.md skills plus MCP (stdio / SSE / HTTP) connect any external service. Feishu / WeCom / Slack / Telegram share the same thread model as the desktop. Switch providers and primary model in Settings.

08 · FOUNDATION

底座：Supervisor · 子代理 · 沙箱 · 记忆中间件 · 工具渐进暴露

Foundation: Supervisor · Subagents · Sandbox · Memory middleware · Progressive tool exposure

这一层不常被当成「全部」来讲，但少了它上面八块都跑不起来——它保证所有一等公民能力真能跑。对外叙事优先级：Plan→验收、工作流、员工审批、自我进化、治理，而不是「又一个 LangGraph demo」。

This layer is rarely the headline, but everything depends on it. We talk about Plan → review, workflows, employee approvals, self-evolution, governance first — not 'yet another LangGraph demo'.

架构总览 Architecture

两层心智：桌面控制平面 + Agent 运行时

Two layers: desktop control plane + Agent runtime

EvoFlow = Agent Runtime（规划、委派、工具、沙箱、恢复）+ 产品控制平面（对话壳、任务、岗位、工作流、治理、扩展）。

EvoFlow = Agent runtime (plan, dispatch, tools, sandbox, recovery) + product control plane (chat, tasks, roles, workflows, governance, extensions).

FAQ

关于 EvoFlow 的常见问题

Frequently asked

EvoFlow 是给开发者用的吗？普通用户能上手吗？ Is EvoFlow only for developers?

不是。主战场是「个人与小团队（约 1～30 人）需要把长任务跑完」——研究者、运营、内容创作者、独立开发都常用。开发者用得深是因为它本身可二次开发；非开发者也能在装好后用 Ask / Agent / Plan / Goal 完成多步工作。

No. The product is for anyone with multi-step work — researchers, ops, creators, indie devs. Developers go deeper because it's hackable, but non-developers ship multi-step work via Ask / Agent / Plan / Goal.

和直接用 LangChain / LangGraph 搭一个 Agent 有什么区别？ How is this different from wiring up LangChain / LangGraph myself?

LangGraph 是 EvoFlow 的底层之一。你拿 LangGraph 写的是「一段编排」，而 EvoFlow 给的是「整套产品控制平面 + 沙箱 + 任务中心 + 岗位 + 治理 + 桌面 UI」。如果只想写段 demo，LangGraph 够；如果要让它真正在桌面/IM 里跑、跑得久、跑得稳、可观测可治理——EvoFlow 直接给你这套车间。

LangGraph is part of EvoFlow's substrate. LangGraph is the orchestration primitive; EvoFlow adds the control plane — sandbox, task center, roles, governance, desktop UI. Use LangGraph for a demo; use EvoFlow when you want it to run, persist, and stay observable in a real product.

我可以接自己的模型吗？ Can I bring my own model?

可以。EvoFlow 在「设置 → 模型」里加服务商与 API Key，主模型随时切；任何 OpenAI 兼容协议都可以接。

Yes. Add providers and API keys in Settings → Models. Any OpenAI-compatible endpoint works.

是不是又一个 DeerFlow 换皮？ Is this a DeerFlow reskin?

不是。EvoFlow 早期参考过 DeerFlow 思路与部分代码（已在 NOTICE 中致谢），但产品形态、运行时、控制平面都已系统性重构为独立产品——加上了桌面 EvoPanel、控制平面、岗位、应用中心、治理与 IM 渠道，是面向长任务的产品。

No. EvoFlow drew early inspiration from DeerFlow (credited in NOTICE), but the runtime, control plane, and product shape are now an independent rebuild — desktop EvoPanel, on-duty posts, App Center, governance, IM channels.
